# adfp-prd-generator

> PRD（产品需求文档）生成器。从功能描述出发，生成结构化产品需求文档。

---

## 基本信息

| 属性 | 值 |
|------|-----|
| **名称** | adfp-prd-generator |
| **类型** | 流水线技能 |
| **阶段** | PRD（在 ANALYZE 和 SPEC 之间） |
| **前缀** | adfp- |
| **触发词** | `生成PRD`、`写PRD`、`产品需求文档`、`prd`、`需求文档`、`帮我整理需求`、`产品规格` |
| **文件位置** | `.claude/skills/adfp-prd-generator/SKILL.md` |

---

## 核心特性

### 1. 结构化需求输出

从零散的功能描述出发，生成 8 个标准章节：
1. 概述（产品背景、目标用户、核心价值）
2. 用户故事（作为/我希望/以便）
3. 功能清单（P0/P1/P2 优先级）
4. 核心交互流程（文本流程图）
5. 验收标准（Given-When-Then）
6. 非功能性需求
7. 约束与假设
8. 附录

### 2. 信息收集

用户未提供时主动询问：
- 目标用户是谁？
- 核心场景有哪些？
- 要解决什么问题？
- 与现有系统/功能的关系？

### 3. 优先级体系

| 优先级 | 含义 |
|--------|------|
| **P0** | 核心功能，MVP 必须实现 |
| **P1** | 重要功能，首版应包含 |
| **P2** | 增强功能，可延后迭代 |

### 4. 双模式输出

| 模式 | 输入 | 输出路径 |
|------|------|---------|
| 敏捷模式 | 用户描述 | `./prd.md` |
| 工程模式 | harness 调度 | `docs/workflows/{任务ID}/prd.md` |

## 使用方式

### 基础用法

```
# 直接描述需求
"帮我写PRD：一个用户管理后台，支持列表查询、新增、编辑、删除"

# 指定触发词
"生成PRD：电商商品详情页"
```

### 指定优先级

```
"这个功能涉及支付，自动P0"
"纯展示类页面默认P1"
```

### 主动使用场景

当用户描述了产品功能但需求散乱，需要结构化成标准PRD格式时，主动触发本技能。

## 流程生命周期

### 触发条件

- **自动触发**：harness 在 ANALYZE 通过后自动进入 PRD 阶段
- **手动触发**："生成PRD"、"写PRD"、"产品需求文档"、"帮我整理需求"
- **跳过条件**：harness 允许从 INIT 直接跳到 PRD（跳过 ANALYZE）

### 生命周期图

```
adfp-requirement-analyzer / 用户描述
      ↓
本技能：信息收集 → 用户故事 → 功能清单 → 交互流程 → 验收标准 → 优先级 → 输出PRD
      ↓
adfp-spec-generator（生成 SPEC）

异常路径：
  ├─ 信息不足 → 主动询问 → 继续生成
  └─ 非前端需求 → 标注边界，仅输出前端相关部分
```

### 在完整流水线中的位置

```
INIT → ANALYZE → 【PRD】 → SPEC → ARCHITECTURE → DESIGN → IMPLEMENT → REVIEW → DONE
```

### 产物状态

| 产物 | 路径 | 状态流转 |
|------|------|---------|
| PRD 文档 | `./prd.md` / `docs/workflows/{任务ID}/prd.md` | 创建 → SPEC 消费 → 归档 |

## 工作流程

### 内部流程

```
信息收集 → 用户故事 → 功能清单 → 交互流程 → 验收标准 → 优先级 → 输出PRD
```

### 详细步骤

1. **信息收集**：解析输入，识别缺失信息，主动询问
2. **用户故事**：按"作为...我希望...以便..."格式生成
3. **功能清单**：拆解功能点，分配优先级（P0/P1/P2）
4. **交互流程**：描述核心用户操作路径
5. **验收标准**：使用 Given-When-Then 格式定义可验收条件
6. **优先级划分**：确保 P0 功能 ≤ 5 个，聚焦 MVP
7. **输出PRD**：生成结构化的 `prd.md` 文档

---

## 与现有技能的职责边界

| 技能 | 职责 | 边界说明 |
|------|------|---------|
| `adfp-requirement-analyzer` | 需求分析、澄清 | PRD 生成的前置步骤，输出需求分析报告 |
| **本技能** | PRD 文档生成 | 接收需求分析，输出结构化 PRD |
| `adfp-spec-generator` | 技术规格生成 | 以 PRD 为输入，输出技术规格文档 |
| `adfp-component-designer` | 组件设计 | 不参与 PRD 阶段，在 DESIGN 阶段工作 |
| `adfp-architecture-designer` | 架构设计 | 不参与 PRD 阶段，在 ARCHITECTURE 阶段工作 |

---

## 约束规则

1. **不确定的信息主动询问，不做假设**
2. **P0 功能 ≤ 5 个**（MVP 聚焦）
3. **验收标准使用 Given-When-Then 格式**
4. **用户故事聚焦用户价值，不写实现细节**
5. **只描述"做什么"，不描述"怎么做"**
6. **每条功能必须有可执行的验收标准**

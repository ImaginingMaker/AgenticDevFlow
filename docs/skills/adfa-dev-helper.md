# adfa-dev-helper

> 前端开发轻量顾问（只读，不管理状态）。三大能力：进度速览、场景分析、下一步建议。

---

## 基本信息

| 属性 | 值 |
|------|-----|
| **名称** | adfa-dev-helper |
| **类型** | 辅助 |
| **前缀** | adfa- |
| **阶段** | 全阶段（只读顾问） |
| **触发词** | `开发助手`、`下一步`、`进度`、`现在该做什么`、`给我建议`、`推荐技能`、`我该用什么技能`、`交互体验`、`找相似组件`、`目录检查`、`搭建骨架`
| **文件位置** | `skills/adfa-dev-helper/SKILL.md` |

---

## 核心特性

### 能力一：进度速览（只读）

扫描 `docs/workflows/` 目录和 `state.json`，输出仪表盘：

```
📊 开发进度仪表盘

活跃任务：2 个
已完成：1 个

| 任务 | 当前阶段 | 进度 | 状态 |
|------|---------|------|------|
| login-page | DESIGN | 4/7 | ✅ 正常 |
| user-list | IMPLEMENT | 5/7 | 🔴 有阻塞 |
```

### 能力二：场景分析

根据用户描述的开发场景，推荐适用的技能和工具：

> **索引源**：`skills/README.md` 是技能注册中心。本表以注册中心为准，新增技能时需同步更新本表。

| 场景 | 推荐技能 | 理由 |
|------|----------|------|
| "我有一个产品想法" | `adfp-prd-generator` | 结构化需求 |
| "需求有了但不知道怎么做" | `adfp-spec-generator` | 生成技术规格 |
| "项目里有哪些可复用的模块" | `adfp-architecture-designer` | SubAgent 并发扫描 |
| "找相似的组件/参考一下" | `adfp-architecture-designer`（快速模式） | 快速匹配Top-5相似组件 |
| "页面怎么拆组件" | `adfp-component-designer` | 设计组件结构 |
| "交互体验怎么做/需要考虑哪些交互状态" | `adfp-component-designer` | 内建UX交互分析，输出四态方案 |
| "帮我写这个组件" | `adfp-code-implementer` | 生成代码 |
| "代码交互缺失，补状态" | `adfp-code-implementer` | 自动补全四态骨架代码 |
| "代码写完了帮看看" | `adfp-code-reviewer` | 审查代码 |
| "这段逻辑能复用吗" | `adfa-hooks-extractor` | 提取 Hook |
| "需要创意方案" | `adfa-brainstorm` | 头脑风暴 |
| "目录太乱了/检查目录规范" | `adft-directory-restructurer` | 审查现存目录或创建骨架 |
| "搭建项目骨架/创建目录结构" | `adft-directory-restructurer`（Preset模式） | 实施前创建目录骨架 |

### 能力三：下一步建议

基于当前阶段给出最优下一步行动：

```
当前阶段 → 产物 → 推荐下一步 → 技能

PRD     → prd.md       → 生成SPEC     → adfp-spec-generator
SPEC    → spec.md      → 架构设计     → adfp-architecture-designer
设计     → design.md   → 实现代码     → adfp-code-implementer
实现     → src/        → 代码审查     → adfp-code-reviewer
```

完整阶段→技能映射见 `adfo-harness-runner/references/phase-registry.md`。

## 流程生命周期

### 触发条件

- **手动触发**："进度"、"下一步"、"开发助手"、"现在该做什么"、"我该用什么技能"
- **主动触发**：用户完成开发步骤后不知道下一步、刚进入项目不清楚从哪开始、描述场景但不知道用哪个技能
- **随时可用**：不限定任何开发阶段，随时可调用

### 生命周期图

```
用户触发
    ↓
本技能（只读）：
  ├─ 进度速览：扫描 docs/workflows/ + state.json → 仪表盘
  ├─ 场景分析：用户描述场景 → 推荐技能
  └─ 下一步建议：读取当前阶段 → 推荐下一步+技能

注意：本技能只读不写，不修改任何状态
```

## 工作流程

### 进度速览流程

```
1. 扫描 docs/workflows/ 目录
   ↓
2. 读取各任务的 state.json
   ↓
3. 汇总任务状态、当前阶段、进度
   ↓
4. 输出仪表盘（对话内）
```

### 场景分析流程

```
1. 接收用户描述的开发场景
   ↓
2. 匹配场景→技能映射表
   ↓
3. 返回推荐技能 + 推荐理由
   ↓
4. 用户确认后可调用推荐技能
```

### 下一步建议流程

```
1. 读取当前任务的 state.json
   ↓
2. 识别当前阶段（PRD/SPEC/DESIGN/IMPLEMENT/REVIEW）
   ↓
3. 查询阶段→技能映射表
   ↓
4. 返回推荐下一步 + 对应技能
```

## 与现有技能的职责边界

### 与 adfo-harness-runner 的区别

| 维度 | adfa-dev-helper | adfo-harness-runner |
|------|---------------|-------------------|
| 读写权限 | **只读** | 读写 |
| 状态管理 | 不修改 state.json | state.json 唯一状态源 |
| 技能调度 | 只推荐，不调用 | 调度原子技能执行 |
| 进度追踪 | 只展示仪表盘 | 更新 phaseHistory |
| 使用场景 | 不知道用哪个技能时 | 正式走流水线时 |
| 产物 | 无（对话输出） | architecture.md、phaseHistory 等 |

### 与其他 adf 技能的关系

| 技能 | 关系 | 说明 |
|------|------|------|
| `adfp-prd-generator` | 推荐下游 | 场景"我有一个产品想法"时推荐 |
| `adfp-spec-generator` | 推荐下游 | 场景"需求有了但不知道怎么做"时推荐 |
| `adfp-architecture-designer` | 推荐下游 | 场景"项目里有哪些可复用的模块"时推荐；含快速相似匹配模式 |
| `adfp-component-designer` | 推荐下游 | 场景"页面怎么拆组件"时推荐；含内建UX交互分析 |
| `adfp-code-implementer` | 推荐下游 | 场景"帮我写这个组件"时推荐；含自动四态骨架生成 |
| `adfp-code-reviewer` | 推荐下游 | 场景"代码写完了帮看看"时推荐；维度4含UX完整性审查 |
| `adfa-hooks-extractor` | 推荐下游 | 场景"这段逻辑能复用吗"时推荐 |
| `adfa-brainstorm` | 推荐下游 | 场景"需要创意方案"时推荐 |
| `adfa-ux-interaction-checker` | 推荐下游 | 场景"深度检查交互体验"时推荐（REVIEW后可选） |
| `adft-directory-restructurer` | 推荐下游 | 场景"目录太乱了"或"搭建项目骨架"时推荐；双模式（Preset+Review） |

## 约束规则

1. **只读原则**：本技能只读取状态，不修改任何文件或状态
2. **基于实际**：基于项目实际状态给出建议，不做无依据的推荐
3. **主动询问**：场景不明确时主动询问，不猜测
4. **附带理由**：推荐技能时必须附带推荐理由
5. **优先读取**：进度追踪优先读取 state.json
6. **尊重用户**：用户说"不需要"时停止建议
7. **无持久化**：所有输出仅在对话内，不生成任何文件

## 测试用例

### 测试用例 1：进度速览

**输入**：
```
用户：进度
```

**预期输出**：
- 扫描 `docs/workflows/` 目录
- 读取各任务 `state.json`
- 输出仪表盘，包含任务列表、当前阶段、进度、状态

- [ ] 正确扫描 workflows 目录

- [ ] 不修改任何文件

**输入**：
```
用户：我有一个产品想法，想做一个登录页面

**验证点**：
- [ ] 正确识别场景
- [ ] 推荐技能正确
- [ ] 附带推荐理由
- [ ] 不自动调用技能

**输入**：
```
用户：下一步做什么

**预期输出**：
- 读取当前任务 state.json

**验证点**：
- [ ] 正确读取 state.json

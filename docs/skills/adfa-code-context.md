## 核心特性

### 5 步分析流程

```
确定入口点 → 读取主文件 → 追踪内部引用链 → 映射逻辑流程 → 输出分析报告
```

### 6 维分析

| 维度 | 覆盖内容 |
|------|----------|
| 入口用途 | 该文件/模块做什么，解决什么问题 |
| 数据流 | 数据从哪里来，如何处理，到哪里去 |
| 核心调用链 | 最关键的函数/方法调用序列 |
| 外部依赖 | 第三方库及其作用 |
| 副作用 | I/O、网络请求、状态变更、事件监听 |
| 关键配置 | 影响行为的配置项或环境变量 |

### 适用场景

- 项目上手：快速理解核心模块
- Bug 调查前：先理解调用链再定位问题
- 代码审查前：建立心智模型提高效率
- 代码审查前：理解后审查
- 学习开源功能：理解他人代码逻辑
- 重构前评估：评估改动影响范围

## 工作流程

### 内部流程

```
1. 确定入口点
   - 解析用户指定的文件路径或模块目录
   - 识别主入口文件（index.ts、main.ts 等）

2. 读取主文件
   - 提取文件结构（函数、类、组件、类型定义）
   - 识别导出接口和公开 API

3. 追踪内部引用链（2-3 层）
   - 解析 import 语句，识别内部依赖
   - 追踪函数调用关系
   - 标注外部 npm 包（不深入源码）

4. 映射逻辑流程
   - 数据流：输入 → 处理 → 输出
   - 控制流：条件分支、循环、异步处理
   - 副作用：网络请求、状态变更、事件监听

5. 输出分析报告
   - 结构化呈现 6 维分析结果
   - 标注关键调用链路径
   - 提供后续建议（审查、重构、测试等）
```

## 与现有技能的职责边界

| 技能 | 边界 |
|------|------|
| `adfp-architecture-designer` | architecture-designer 扫描**整个项目**识别模块和依赖拓扑（宏观），code-context 追踪**单个文件/模块**内部的调用链和数据流（微观） |
| `adfa-hooks-extractor` | code-context **理解代码逻辑和数据流**，hooks-extractor 专门**提取可复用的 Hook 逻辑** |
| `adfp-code-reviewer` | code-context **建立心智模型**（理解代码在做什么），code-reviewer **评估质量**（检查代码是否做好） |
| `adfa-critical-explorer` | critical-explorer 审查**设计方案**（编码前），code-context 理解**已有代码**（编码后） |
| `adfa-edge-case-master` | code-context **理解代码逻辑**，edge-case-master **生成边界测试用例** |
| `adft-page-wiki-generator` | page-wiki-generator 生成**页面级**的链路 Wiki，code-context 分析**模块级**的代码上下文 |

## 约束规则

1. **不重复粘贴大段源码**，只提炼关键信息
2. **外部 npm 包只说明用途**，不深入源码
3. **追踪深度默认 2-3 层**，过深时截断并标注
4. **优先主路径清晰度**，非完整覆盖所有边缘
5. **工具函数、类型文件、样式文件**跳过或简要提及
6. **产物不落盘**，仅在对话内输出

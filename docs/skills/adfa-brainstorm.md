# adfa-brainstorm
> 轻量级头脑风暴引导器。快速启动创意会议，支持多维度发散思维。

## 基本信息

| 属性 | 值 |
|------|-----|
| **名称** | adfa-brainstorm |
| **类型** | 辅助 |
| **前缀** | adfa-（AgenticDevFlow Assistance） |
| **触发词** | `头脑风暴`、`brainstorm`、`帮我想点子`、`创意发散`、`集思广益`、`帮我想想办法`、`有什么思路` |
| **文件位置** | `.claude/skills/adfa-brainstorm/SKILL.md` |

## 核心特性

- **敏捷启动**：30秒内开始，不冗长解释方法论
- **三种模式**：快闪(5分钟) / 标准(15分钟) / 深度(30分钟)
- **15 种发散技术**：创意突破、系统结构、催化刺激、探索挖掘四大类
- **反偏见协议**：每 8-10 个想法强制切换正交维度
- **教练式引导**：延伸用户想法而非问答式记录
- **双模式支持**：独立敏捷模式 / harner 工程模式

## 使用方式

### 基础用法
```
/adfa-brainstorm
"帮我头脑风暴一个新功能的命名"
```

### 指定模式
```
"5分钟快闪头脑风暴命名"          # 快闪模式
"标准头脑风暴架构方案"            # 标准模式
"深度头脑风暴产品定位"            # 深度模式
```

## 依赖关系

### 下游消费（谁依赖本技能）

| 技能 | 关系类型 | 说明 |
|------|---------|------|
| `adfp-requirement-analyzer` | 后置消费 | 需求模糊时触发快速模式，收敛结果作为分析素材 |
| `adfo-harness-runner` | 可选触发 | ANALYZE 阶段前可调度 brainstorm 探索方向 |
| `adfa-dev-helper` | 建议下游 | 用户说"需要创意方案"时推荐本技能 |

## 流程生命周期

### 触发条件
- **手动触发**：用户说"头脑风暴"、"brainstorm"、"帮我想点子"等
- **下游回调**：`adfp-requirement-analyzer` 在需求模糊时调用快速模式
- **编排调度**：`adfo-harness-runner` 在 ANALYZE 前调度

### 生命周期图

```
用户输入（话题 + 模式）
  │
  ├─ Step 1: 模式选择（完整/快速/快闪）
  ├─ Step 2: 发散阶段（2-5 轮，每轮 3-5 个想法）
  │     ├─ 能量检查点（每 4 轮）
  │     └─ 正交维度切换（每 8 个想法）
  ├─ Step 3: 收敛阶段（主题聚类 → Top 3 → 行动建议）
  └─ Step 4: 产物输出（按模式选择路径）

异常路径：
  ├─ 用户能量耗尽 → 强制收敛
  ├─ 用户偏离主题 → 提醒并询问
  ├─ 用户中断 → 立即停止
  └─ 用户连续拒绝 → 切换极端技术
```

### 在完整流水线中的位置

```
INIT → 【BRAINSTORM（可选前置）】→ ANALYZE → PRD → ... → DONE
```

ANALYZE 的可选前置阶段，仅在需求模糊时触发。

### 产物状态

| 产物 | 路径 | 状态流转 |
|------|------|---------|
| 头脑风暴报告 | 敏捷：`brainstorm-<主题>.md` / 工程：`docs/workflows/{任务ID}/brainstorm.md` | 创建 → 被 `adfp-requirement-analyzer` 消费 → 归档 |
| 快速模式返回值 | 不落盘 | 直接传递给调用方 → 调用方解析引用 |

## 与现有技能的职责边界

| 维度 | adfa-brainstorm | adfp-requirement-analyzer |
|------|-----------------|--------------------------|
| **阶段** | **探索发散**（ANALYZE 之前） | **收敛结构化**（ANALYZE） |
| **目标** | 帮用户发现自己想要什么 | 将想法落地为可执行的需求分析 |
| **触发条件** | 用户需求模糊，无明确方向 | 用户需求清晰（或 brainstorm 已收敛） |
| **关系** | requirement-analyzer 的**前置步骤** | brainstorm 的**下游消费者** |

| 维度 | adfa-brainstorm | adfa-critical-explorer |
|------|-----------------|----------------------|
| **方向** | **发散创意**，从无到有生成想法 | **批判收敛**，审视已有方案的质量 |
| **阶段** | 项目早期（需求未定义时） | 方案成型后（SPEC/DESIGN 阶段） |

## 约束规则

1. 用户说"停"立即停止，不强制完成流程
2. 每 8-10 个想法强制切换正交维度，避免语义聚类
3. 不评判想法质量，先追求数量再收敛
4. 不替代用户做最终决策
5. 工程模式下产物归入 `docs/workflows/{任务ID}/`

## 模板注入

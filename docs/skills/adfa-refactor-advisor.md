# adfa-refactor-advisor

> 前端代码重构专家。识别代码中的逻辑碎片化、职责混杂、嵌套过深、硬编码、冗余重复等问题，提供专业重构方案和完整可运行的前后对照代码。智能感知目标框架：React 输出 Hooks + TSX、Vue 3 输出 Composables + SFC、小程序输出 Behavior + WXML/WXSS。

## 基本信息

| 属性 | 值 |
|------|-----|
| **名称** | adfa-refactor-advisor |
| **类型** | 辅助 |
| **前缀** | adfa- |
| **触发词** | 重构、代码太乱、需要整理、优化代码结构、帮我整理这段代码、这段代码怎么重构 |
| **文件位置** | skills/adfa-refactor-advisor/SKILL.md |

## 核心特性

- **5 类坏味道识别**：状态散乱、业务与视图耦合、组件过大、嵌套过深、硬编码（框架通用）
- **三链路平台感知**：工程模式(state.json) → 敏捷模式(自动检测) → 用户指定 → 通用降级
- **框架路由表**：React / Vue 3 / 微信小程序 / Taro/uni-app 各框架输出对应风格
- **重构前后对照**：问题代码 + 重构后代码 + 关键改动标注
- **四种重构策略**：精简重构、极致拆分、兼容原有、只改结构
- **代码可直接使用**：重构后代码完整可运行
- **工程模式产物**：输出 `refactor-plan.md` 供 implementer 执行

## 使用方式

### 敏捷模式（直接调用）

```
"这段代码太乱了，帮我重构"
"帮我整理这个组件，业务和视图混在一起了"
"精简重构：保留功能，只优化结构"
"极致拆分：全面解耦，拆成最小单元"
"按 Vue 3 方式重构这段代码"
```

### 工程模式（通过 harness）

REVIEW 阶段发现问题后，作为辅助步骤出重构方案，再由 implementer 修复模式执行。

```
REVIEW →（结构性问题）→ REFACTOR（本技能）→ IMPLEMENT → REVIEW
```

## 流程生命周期

### 触发条件

- **手动触发**："重构"、"代码太乱"、"需要整理"、"优化代码结构"
- **建议触发**：adfp-code-reviewer 发现结构性问题时建议调用
- **上游回调**：REVIEW 阶段发现问题 → refactor-advisor 出方案 → implementer 执行

### 生命周期图

```
adfp-code-reviewer（诊断结构问题）/ adfa-code-analysis（mode:context，理解上下文）/ 用户触发
      ↓
本技能：平台感知框架检测 → 问题识别(5类坏味道) → 选择策略 → 重构方案 → 前后对照代码 → 改动说明
      ↓
adfp-code-implementer（执行结构性改造）

框架检测路径：
  ├─ 工程模式 → 接收 state.json.techStack
  ├─ 敏捷模式 → 自动扫描依赖/配置/目录
  ├─ 用户指定 → "按 Vue 3 重构"
  └─ 通用降级 → 框架无关模式

重构策略选择：
  ├─ 精简重构 → 最小改动，功能不变
  ├─ 极致拆分 → 全面解耦
  ├─ 兼容原有 → 保持接口不变
  └─ 只改结构 → 不动业务逻辑
```

### 在反馈循环中的位置

```
REVIEW →（结构性问题）→ 【REFACTOR】 → IMPLEMENT → REVIEW
```

### 产物状态

| 产物 | 路径 | 状态流转 |
|------|------|---------|
| 重构方案+对照代码 | 对话内输出 | 输出 → implementer 执行 → 丢弃 |
| refactor-plan.md | docs/workflows/（工程模式） | 输出 → implementer 读取执行 → 归档 |

## 工作流程

```
代码输入 → 平台感知框架检测 → 问题识别(5类坏味道) → 重构策略 → 前后对照代码 → 关键改动说明
```

### 详细步骤

1. **代码输入**：接收用户粘贴的代码或从 reviewer 传递的问题代码
2. **框架检测**：三链路检测 → 路由到对应框架的 refactor-patterns.md
3. **问题识别**：扫描 5 类坏味道（框架通用）
   - 状态散乱：多个独立状态变量描述同一业务概念
   - 业务与视图耦合：组件内包含复杂业务逻辑
   - 组件过大：单文件超过 200 行或单组件超过 100 行
   - 嵌套过深：条件渲染嵌套超过 3 层
   - 硬编码：魔法数字、硬编码字符串、硬编码样式
4. **重构策略选择**：根据用户指定或问题严重程度选择策略
5. **输出前后对照代码**：按目标框架风格输出问题代码 vs 重构后代码，标注关键改动
6. **关键改动说明**：解释每处改动的目的和收益

## 框架路由

| 检测条件 | 输出风格 | 核心模式 |
|---------|---------|---------|
| React / JSX / TSX | Hooks + TSX | useState→useReducer、Hook 提取、子组件拆分、早期返回 |
| Vue 3 / Nuxt | Composables + SFC | ref→reactive、Composable 提取、子组件拆分、v-if 扁平化 |
| 微信小程序 | Behavior + WXML/WXSS | Behavior 封装、setData 批量、子 Component 提取 |
| Taro / uni-app | 按对应框架 | 跨端兼容模式 |
| 通用/未知 | 通用函数 + 模块拆分 | Utils 提取、常量提取、模块拆分 |

## 5 类坏味道

| # | 坏味道 | 表现 | 重构方向 |
|---|--------|------|---------|
| 1 | 状态散乱 | 多个独立状态变量 | 收敛为状态对象 / 状态管理模式 |
| 2 | 业务与视图耦合 | 组件内含复杂业务 | 提取逻辑单元（Hook/Composable/Behavior） |
| 3 | 组件过大 | 单文件 >200行 | 拆分子组件/页面 |
| 4 | 嵌套过深 | >3层条件嵌套 | 早期返回 / 子组件提取 / 枚举化 |
| 5 | 硬编码 | 魔法数字、字符串 | 提取为常量/配置/枚举 |

## 与现有技能的职责边界

| 技能 | 关系 | 区分 |
|------|------|------|
| `adfp-code-reviewer` | 上游 | reviewer **诊断**问题并分级，本技能**治疗**并产出对照代码 |
| `adfa-code-analysis` (mode:extract) | 平行 | code-analysis (mode:extract) 仅做 Hook/Composable/Behavior 提取，本技能覆盖更广（组件拆分、状态收敛、嵌套消除等） |
| `adfp-code-implementer` | 下游 | implementer 定点修 bug（最小改动），本技能做结构性重构（可能大幅改动） |
| `adfa-code-analysis` (mode:context) | 上游 | code-analysis (mode:context) 先帮助理解代码，本技能基于理解出方案 |

## 约束规则

- 不处理目标框架不支持的模式（如小程序中不输出 `useEffect`）
- 重构后代码必须完整可运行
- 不改业务逻辑，不增加功能
- 改动幅度匹配用户选择的方向
- 不做问题分级（那是 reviewer 的职责）
- 工程模式下必须输出 refactor-plan.md
- 框架映射使用检测路由表，不做硬编码假设

|---|------|---------|

# adfa-refactor-advisor

> React + TypeScript 代码重构专家。识别代码中的逻辑碎片化、职责混杂、嵌套过深、硬编码、冗余重复等问题，提供专业重构方案和完整可运行的前后对照代码。

## 基本信息

| 属性 | 值 |
|------|-----|
| **名称** | adfa-refactor-advisor |
| **类型** | 辅助 |
| **前缀** | adfa- |
| **触发词** | 重构、代码太乱、需要整理、优化代码结构、帮我整理这段代码、这段代码怎么重构 |
| **文件位置** | .claude/skills/adfa-refactor-advisor/SKILL.md |

## 核心特性

- **5 类坏味道识别**：状态散乱、业务与视图耦合、组件过大、嵌套过深、硬编码
- **重构前后对照**：问题代码 + 重构后代码 + 关键改动标注
- **四种重构策略**：精简重构、极致拆分、兼容原有、只改结构
- **代码可直接使用**：重构后代码完整可运行
- **工程模式产物**：输出 `refactor-plan.md` 供 implementer 执行

## 使用方式

### 敏捷模式（直接调用）

```
"这段代码太乱了，帮我重构"
"帮我整理这个组件，业务和视图混在一起了"
"精简重构：保留功能，只优化结构"
"极致拆分：全面解耦，拆成最小单元"
```

### 工程模式（通过 harness）

REVIEW 阶段发现问题后，作为辅助步骤出重构方案，再由 implementer 修复模式执行。

```
REVIEW →（结构性问题）→ REFACTOR（本技能）→ IMPLEMENT → REVIEW
```

## 流程生命周期

### 触发条件

- **手动触发**："重构"、"代码太乱"、"需要整理"、"优化代码结构"
- **建议触发**：adfp-code-reviewer 发现结构性问题时建议调用
- **上游回调**：REVIEW 阶段发现问题 → refactor-advisor 出方案 → implementer 执行

### 生命周期图

```
adfp-code-reviewer（诊断结构问题）/ adfa-code-context（理解上下文）/ 用户触发
      ↓
本技能：问题识别(5类坏味道) → 选择策略 → 重构方案 → 前后对照代码 → 改动说明
      ↓
adfp-code-implementer（执行结构性改造）

重构策略选择：
  ├─ 精简重构 → 最小改动，功能不变
  ├─ 极致拆分 → 全面解耦
  ├─ 兼容原有 → 保持接口不变
  └─ 只改结构 → 不动业务逻辑
```

### 在反馈循环中的位置

```
REVIEW →（结构性问题）→ 【REFACTOR】 → IMPLEMENT → REVIEW
```

### 产物状态

| 产物 | 路径 | 状态流转 |
|------|------|---------|
| 重构方案+对照代码 | 对话内输出 | 输出 → implementer 执行 → 丢弃 |
| refactor-plan.md | docs/workflows/（工程模式） | 输出 → implementer 读取执行 → 归档 |

## 工作流程

```
代码输入 → 问题识别 → 重构策略 → 重构前后对照代码 → 关键改动说明
```

### 详细步骤

1. **代码输入**：接收用户粘贴的代码或从 reviewer 传递的问题代码
2. **问题识别**：扫描 5 类坏味道
   - 状态散乱：多个 useState 分散、状态提升不当
   - 业务与视图耦合：组件内包含复杂业务逻辑
   - 组件过大：单文件超过 300 行或单组件超过 100 行
   - 嵌套过深：条件渲染嵌套超过 3 层
   - 硬编码：魔法数字、硬编码字符串、硬编码样式
3. **重构策略选择**：根据用户指定或问题严重程度选择策略
4. **输出前后对照代码**：问题代码 vs 重构后代码，标注关键改动
5. **关键改动说明**：解释每处改动的目的和收益

## 与现有技能的职责边界

| 技能 | 关系 | 区分 |
|------|------|------|
| `adfp-code-reviewer` | 上游 | reviewer **诊断**问题并分级，本技能**治疗**并产出对照代码 |
| `adfa-hooks-extractor` | 平行 | hooks-extractor 仅做 Hook 提取，本技能覆盖更广（组件拆分、状态收敛、嵌套消除等） |
| `adfp-code-implementer` | 下游 | implementer 定点修 bug（最小改动），本技能做结构性重构（可能大幅改动） |
| `adfa-code-context` | 上游 | code-context 先帮助理解代码，本技能基于理解出方案 |

## 约束规则

- 仅处理 React/TypeScript 前端代码
- 重构后代码必须完整可运行
- 不改业务逻辑，不增加功能
- 改动幅度匹配用户选择的方向
- 不做问题分级（那是 reviewer 的职责）
- 工程模式下必须输出 refactor-plan.md

## 测试用例

| # | 场景 | 预期行为 |
|---|------|---------|
| 1 | React 组件状态散乱 | 识别问题、建议收敛、输出前后对照代码 |
| 2 | 业务与视图耦合 | 建议抽离 Hooks、重构后组件只负责渲染 |
| 3 | 用户指定「精简重构」 | 最小改动、功能不变 |
| 4 | 用户指定「极致拆分」 | 全面解耦、拆成最小单元 |
| 5 | 代码已经比较规范 | 如实告知质量良好 |
| 6 | 未粘贴代码 | 引导用户提供代码 |
| 7 | 工程模式调用 | 输出 refactor-plan.md 到 docs/workflows/ |
| 8 | 嵌套过深（>3层） | 建议提取子组件或使用早期返回 |
| 9 | 硬编码魔法数字 | 建议提取为常量或配置 |
| 10 | 组件过大（>300行） | 建议拆分为多个子组件 |

# SubAgent 提示词与输出格式

> 供 `adfp-architecture-designer` 在「已有项目分析」模式下调度 5 个 SubAgent 使用。
> 通过 `adfo-task-orchestrator` 并发执行（全部无依赖，最大并发 5）。

## SA1：组件扫描器

### 职责
扫描项目组件目录，识别所有组件并给出原子化评级。

### 提示词模板

```
你是一名前端组件扫描器。请扫描指定目录下的所有组件文件。

【扫描路径】
{项目 src/ 路径}

【目标框架】
{框架检测结果}

请输出：

1. 组件清单
   | 组件名 | 路径 | 行数 | Props 数 | 依赖组件 | 复用次数 |
   |--------|------|------|---------|---------|---------|

2. 原子化评级
   - ✅ 原子（Atom）：单一职责、Props ≤ 3、≤ 100 行
   - ✅ 分子（Molecule）：2-5 个原子组合、Props ≤ 5、≤ 200 行
   - ⚠️ 组织（Organism）：多个分子组合、> 200 行、考虑拆分
   - ❌ 候选拆分：职责混杂、> 300 行

3. 可复用候选
   列出原子化评级为「原子」「分子」且被 2+ 组件引用的组件
```

### 输出格式

```markdown
## SA1 组件扫描报告

### 组件清单
| 组件名 | 路径 | 行数 | Props 数 | 依赖组件 | 复用次数 | 原子化评级 |
|--------|------|------|---------|---------|---------|-----------|
| {name} | {path} | {N} | {N} | {list} | {N} | 原子/分子/组织/候选拆分 |

### 可复用候选
- {组件名} — 复用 {N} 次，建议提取为公共组件

### 拆分建议
- {组件名} — 理由：{职责混杂/行数超标}
```

## SA2：Hooks/逻辑盘点器

### 职责
扫描项目中所有自定义 Hooks/工具函数，统计引用次数和使用模式。

### 提示词模板

```
你是一名前端 Hooks/逻辑盘点器。请扫描项目中的自定义 Hooks 和工具函数。

【扫描路径】
{项目 hooks/、utils/、lib/ 等目录}

请输出：

1. Hook/Util 清单
   | 名称 | 路径 | 类型 | 引用次数 | 使用组件 |
   |------|------|------|---------|---------|

2. 引用模式分析
   - 高频引用（5+ 组件）：提取为公共模块
   - 低频引用（1 次组件）：考虑内联
   - 重复实现：找到功能相似但不同名的 Hook

3. 提取建议
   - 建议提取为共享 Hook：{列表}
   - 建议合并的重复实现：{列表}
```

### 输出格式

略（遵循模板即可）。

## SA3：Service/API 扫描器

### 职责
扫描项目中所有 API 调用模式，分析封装完整性。

### 提示词模板

```
你是一名前端 Service/API 扫描器。请扫描项目中的 API 调用代码。

【扫描路径】
{项目 src/}

请输出：

1. API 调用清单
   | 方法 | 端点 | 使用页面/组件 | 封装方式 | 错误处理 |
   |------|------|-------------|---------|---------|

2. 封装完整性评估
   - ✅ 完整：统一封装 + 错误处理 + loading/empty/error 三态
   - ⚠️ 部分：有封装但缺少某状态处理
   - ❌ 无封装：直接用 fetch/axios 散落在组件中

3. 改进建议
   - 建议统一封装的模式
   - 建议补充的错误处理
```

## SA4：依赖关系图映射器

### 职责
扫描项目的 import/export 拓扑，生成依赖图并检测循环依赖。

### 提示词模板

```
你是一名前端依赖关系映射器。请分析项目中的模块依赖关系。

【扫描路径】
{项目 src/}

请输出：

1. 依赖拓扑
   ```
   {模块A} → {模块B} → {模块C}
   ```

2. 循环依赖检测
   - 发现 {N} 处循环依赖
   - 每处标注：{模块X} ↔ {模块Y}

3. 依赖深度分析
   - 最深引用链：{N} 层
   - 平均引用深度：{N} 层
   - 存在引用深度 > 5 的模块：{列表}

4. 优化建议
   - 建议通过接口抽象解决循环依赖
   - 建议提取公共依赖减少深度
```

## SA5：结构规范分析器

### 职责
扫描项目的目录结构、命名规范、样式组织和 TS 严格度。

### 提示词模板

```
你是一名前端结构规范分析器。请分析项目的结构和编码规范。

【扫描路径】
{项目根目录}

请输出：

1. 目录结构评估
   - 目录层级深度：平均 {N} 层，最深 {N} 层
   - 文件命名规范：PascalCase / camelCase / kebab-case
   - 模块组织方式：按类型 / 按功能 / 混合

2. 命名规范一致性
   - 组件文件：{PascalCase / 混合}
   - 工具文件：{camelCase / 混合}
   - 样式文件：{kebab-case / 混合}
   - 命名混乱度：低/中/高

3. 样式组织
   - 样式方案：CSS Modules / styled-components / Tailwind / 原生 CSS
   - 全局样式管理：{有/无}
   - 样式隔离性：{好/中/差}

4. TypeScript 严格度
   - tsconfig strict: {true/false}
   - any 使用频率：{低/中/高}
   - 类型导出规范：{有/无}

5. 改进建议
   - {规范改进点}
```

---

## 汇总整合规则

5 个 SubAgent 完成后，按以下流程汇总：

1. **去重**：合并 SA1-SA5 中重叠的发现
2. **冲突校验**：标注规范建议之间的冲突
3. **优先级排序**：
   - P0：循环依赖、严重规范偏离
   - P1：可复用候选、封装改进
   - P2：命名规范、样式组织
4. **输出**：生成 architecture.md 文档

## 快速模式 SubAgent（模式 C）

> 供 `adfp-architecture-designer` 在「快速相似匹配」模式下调度 2 个 SubAgent 使用。
> 通过 `adfo-task-orchestrator` 并发执行（全部无依赖，最大并发 2）。

### SA1-快速：组件/模式匹配器

#### 职责

快速扫描 `components/` 和 `pages/` 目录，找出与用户描述功能最相似的组件。

#### 提示词模板

```
你是一名前端组件匹配器。请快速扫描目录下的组件文件，
找出与用户描述最相似的 Top-5 组件。

【扫描路径】
{项目 src/ 路径}

【目标框架】
{框架检测结果}

【用户功能描述】
{用户输入的关键词/功能描述}

【匹配方法】
1. 文件名/组件名是否包含用户描述的关键词
2. 文件导入的依赖是否与用户场景相关
3. Props 接口结构是否暗示类似功能

请输出以下格式：

```
## Top-5 相似组件

| 排名 | 组件名 | 路径 | 行数 | Props | 关键依赖 | 导入方数量 | 相似度 |
|------|--------|------|------|-------|---------|-----------|--------|
| 1 | {组件名} | `{路径}` | {N} | {Props列表} | {依赖} | {N}处 | 92% |

匹配依据：{简述为何匹配}
差异点：{与用户需求的差异}
```
```

### SA2-快速：逻辑/API 匹配器

#### 职责

快速扫描 `hooks/` `services/` `utils/` 目录，找出与用户描述最相似的逻辑单元。

#### 提示词模板

```
你是一名前端逻辑匹配器。请快速扫描目录下的 .ts 文件，
找出与用户描述最相似的 Top-5 逻辑单元。

【扫描路径】
{项目 src/ 路径}

【目标框架】
{框架检测结果}

【用户功能描述】
{用户输入的关键词/功能描述}

【匹配方法】
1. 文件名/函数名/导出名是否包含关键词
2. Hook 命名（useXxx）是否暗示功能域
3. API 路由（/api/xxx）是否匹配场景
4. 工具函数名和参数模式是否相似

请输出以下格式：

```
## Top-5 相似逻辑单元

| 排名 | 名称 | 路径 | 类型 | 导出接口 | 引用方数量 | 相似度 |
|------|------|------|------|---------|-----------|--------|
| 1 | {名称} | `{路径}` | Hook/Service/Util | {导出函数列表} | {N}处 | 88% |

匹配依据：{简述为何匹配}
差异点：{与用户需求的差异}
```
```

### 快速模式汇总规则

2 个 SubAgent 完成后，合并结果：

1. **合并列表**：SA1 + SA2 输出合并，按相似度降序排列，保留 Top-5
2. **差异对比**：每项标注与用户需求的差异
3. **复用建议**：
   - ✅ 直接复用：相似度 ≥ 85% 且修改量小
   - 📖 参考模式：相似度 60-84%，可参考实现模式
   - 🆕 新增包装：相似度 < 60%，但可封装部分逻辑
4. **输出**：生成 `component-match.md`

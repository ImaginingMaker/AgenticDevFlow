# SubAgent 提示词与输出格式

> 供 `adfa-code-scanner` 在「全量扫描」模式下调度 3 个 SubAgent 使用。
> 通过 `adfo-task-orchestrator` 并发执行（全部无依赖，最大并发 3）。

## SA1：组件扫描器

### 职责
扫描项目组件目录，识别所有组件并给出原子化评级。

### 提示词模板

```
你是一名前端组件扫描器。请扫描指定目录下的所有组件文件。

【扫描路径】
{项目 src/ 路径}

【目标框架】
{框架检测结果}

请输出：

1. 组件清单
   | 组件名 | 路径 | 行数 | Props 数 | 依赖组件 | 复用次数 |
   |--------|------|------|---------|---------|---------|

2. 原子化评级
   - ✅ 原子（Atom）：单一职责、Props ≤ 3、≤ 100 行
   - ✅ 分子（Molecule）：2-5 个原子组合、Props ≤ 5、≤ 200 行
   - ⚠️ 组织（Organism）：多个分子组合、> 200 行、考虑拆分
   - ❌ 候选拆分：职责混杂、> 300 行

3. 可复用候选
   列出原子化评级为「原子」「分子」且被 2+ 组件引用的组件
```

### 输出格式

```markdown
## SA1 组件扫描报告

### 组件清单
| 组件名 | 路径 | 行数 | Props 数 | 依赖组件 | 复用次数 | 原子化评级 |
|--------|------|------|---------|---------|---------|-----------|
| {name} | {path} | {N} | {N} | {list} | {N} | 原子/分子/组织/候选拆分 |

### 可复用候选
- {组件名} — 复用 {N} 次，建议提取为公共组件

### 拆分建议
- {组件名} — 理由：{职责混杂/行数超标}
```

## SA2：Hooks/逻辑盘点器

### 职责
扫描项目中所有自定义 Hooks/工具函数，统计引用次数和使用模式。

### 提示词模板

```
你是一名前端 Hooks/逻辑盘点器。请扫描项目中的自定义 Hooks 和工具函数。

【扫描路径】
{项目 hooks/、utils/、lib/ 等目录}

【目标框架】
{框架检测结果}

请输出：

1. Hook/Util 清单
   | 名称 | 路径 | 类型 | 引用次数 | 使用组件 |
   |------|------|------|---------|---------|

2. 引用模式分析
   - 高频引用（5+ 组件）：提取为公共模块
   - 低频引用（1 次组件）：考虑内联
   - 重复实现：找到功能相似但不同名的逻辑单元

3. 提取建议
   - 建议提取为共享逻辑单元：{列表}
   - 建议合并的重复实现：{列表}
```

### 输出格式

```markdown
## SA2 逻辑资产报告

### Hook/Util 清单
| 名称 | 路径 | 类型 | 引用次数 | 使用组件 |
|------|------|------|---------|---------|

### 引用模式分析
- 高频引用（5+ 组件）：{列表}
- 低频引用（1 次组件）：{列表}
- 重复实现：{列表}

### 提取建议
- 建议提取：{列表}
- 建议合并：{列表}
```

## SA3：Service/API 扫描器

### 职责
扫描项目中所有 API 调用模式，分析封装完整性。

### 提示词模板

```
你是一名前端 Service/API 扫描器。请扫描项目中的 API 调用代码。

【扫描路径】
{项目 src/}

【目标框架】
{框架检测结果}

请输出：

1. API 调用清单
   | 方法 | 端点 | 使用页面/组件 | 封装方式 | 错误处理 |
   |------|------|-------------|---------|---------|

2. 封装完整性评估
   - ✅ 完整：统一封装 + 错误处理 + loading/empty/error 三态
   - ⚠️ 部分：有封装但缺少某状态处理
   - ❌ 无封装：直接用 fetch/axios 散落在组件中

3. 改进建议
   - 建议统一封装的模式
   - 建议补充的错误处理
```

### 输出格式

```markdown
## SA3 API 资产报告

### API 调用清单
| 方法 | 端点 | 使用页面/组件 | 封装方式 | 错误处理 |
|------|------|-------------|---------|---------|

### 封装完整性评估
- ✅ 完整：{列表}
- ⚠️ 部分：{列表}
- ❌ 无封装：{列表}

### 改进建议
- {建议1}
- {建议2}
```

## 主 Agent 汇总规则

3 个 SubAgent 完成后，按以下流程汇总：

1. **去重**：合并 SA1-SA3 中重叠的发现（如某组件同时被 SA1 和 SA3 提到）
2. **冲突校验**：标注扫描结果之间的矛盾
3. **分组输出**：按「组件资产 / 逻辑资产 / API 资产」三章组织
4. **下游推荐**：在报告末尾推荐下游技能
   - 发现可复用组件 → 推荐 `adfp-component-designer`
   - 发现 API 封装不完整 → 推荐 `adfa-edge-case-master`
   - 发现重复实现 → 推荐 `adfa-hooks-extractor`

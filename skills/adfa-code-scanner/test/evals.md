# adfa-code-scanner - 评估用例

## 核心场景

### 模式 A：全量扫描

| # | 场景 | 预期行为 | 验证方式 |
|---|------|---------|---------|
| 1 | 用户说"扫描一下项目中有哪些组件" | 进入全量扫描模式，并发 3 SA | 产出 `code-scan-report.md`，含组件/逻辑/API 三章 |
| 2 | React 项目全量扫描 | SA1 扫描 `components/` 下的 `.tsx` 文件 | 输出组件清单，正确标记原子化评级 |
| 3 | Vue 3 项目全量扫描 | SA1 扫描 `components/` 下的 `.vue` 文件 | 输出组件清单，正确标记原子化评级 |
| 4 | 小程序项目全量扫描 | SA1 扫描 `components/` + `pages/` 下的 `.wxml` | 输出页面组件清单 |
| 5 | SA2 逻辑盘点 | 扫描 hooks/utils 目录 | 输出 Hook/Util 清单 + 引用次数 |
| 6 | SA3 API 扫描 | 扫描 services/api 目录 | 输出 API 清单 + 封装评估 |
| 7 | 平台感知 — 工程模式 | 从 `state.json.techStack` 读取框架 | 直接路由到对应框架扫描策略 |
| 8 | 平台感知 — 敏捷模式 | 扫描 `package.json` 检测框架 | 正确检测并使用 |

### 模式 B：快速相似匹配

| # | 场景 | 预期行为 | 验证方式 |
|---|------|---------|---------|
| 9 | 用户说"项目中有没有类似的搜索功能" | 进入快速匹配模式，并发 2 SA | 产出 `component-match.md`，含 Top-5 + 相似度 + 复用建议 |
| 10 | 已有匹配项 | SA1-快速返回 Top-5 组件，SA2-快速返回 Top-5 逻辑 | 合并后按相似度排序，保留 Top-5 |
| 11 | 无匹配项 | 未发现相似组件和逻辑 | 输出"未发现明显相似项，建议从零实现" |

## 边界测试

| # | 边界情况 | 预期处理 |
|---|---------|---------|
| 1 | 空项目（无代码） | 模式 A：输出空清单，提示无资产；模式 B：提示不适用 |
| 2 | 仅单一步骤的快速模式触发词出现在全量扫描上下文中 | 按路由规则正确判定模式 |
| 3 | 无 package.json 且无框架配置文件 | 降级为通用扫描，提示用户可指定框架 |
| 4 | 扫描路径不存在 | 提示路径不存在，询问用户确认路径 |
| 5 | 超大型项目（1000+ 文件） | SA 任务中标注扫描范围，优先扫描核心目录 |
| 6 | 混合框架项目（如 Taro + React） | 按检测路由表优先匹配，标注多框架发现 |

## 集成测试

| # | 上下游技能 | 集成点 | 预期 |
|---|----------|--------|------|
| 1 | `adfp-architecture-designer`（上游） | scanner 输出清单 → architecture-designer 做架构决策 | architecture-designer 消费扫描结果，不重复扫描 |
| 2 | `adfp-code-implementer`（下游） | IMPLEMENT 前调用 scanner 了解可复用资产 | implementer 直接引用扫描报告中的可复用组件 |
| 3 | `adfa-hooks-extractor`（互补） | scanner 发现重复实现 → 推荐 hooks-extractor | 报告末尾包含下游技能推荐 |
| 4 | `adfa-edge-case-master`（下游） | scanner 发现 API 封装不完整 → 推荐 edge-case-master | 报告末尾包含测试生成推荐 |
| 5 | `adfo-task-orchestrator`（调度） | 委托 3 SA（全量）或 2 SA（快速）并发调度 | 全部无依赖，正确执行并返回汇总 |

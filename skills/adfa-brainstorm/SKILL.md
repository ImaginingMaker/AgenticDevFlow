# 轻量级头脑风暴

> 入口页。发散技术库见 `references/techniques.md`；引导与收敛流程见 `references/facilitation.md`。

**核心原则：快速启动 → 多维发散 → 敏捷收敛**

---

## 关键心态

- **保持发散模式**：最佳头脑风暴会让人感到"轻微不适"
- **抵抗组织冲动**：除非用户要求，否则不提议整理
- **数量解锁质量**：前 20 个想法通常是显而易见的。魔法在第 50-100
- **反偏见协议**：每 8-10 个想法后强制切换到正交领域

---

## 启动模式

| 模式 | 时间 | 想法数 | 适用场景 |
|------|------|--------|----------|
| `快闪` | 5 分钟 | 15-20 | 快速收集初步想法 |
| `标准` | 15 分钟 | 30-40 | 常规创意会议 |
| `深度` | 30 分钟 | 50+ | 复杂问题全面探索 |

**调用方指定模式**：下游技能调用时明确 `模式: 快速`，跳过会话存储，产出精简结果后立即返回。

---

## 核心流程概览

```
启动 → 发散(2-5轮，每轮3-5想法) → 能量检查点 → 收敛(主题聚类→Top3→行动) → 输出
```

| 步骤 | 说明 | 详情 |
|------|------|------|
| 发散 | 使用发散技术库（`references/techniques.md`）生成想法 | 每轮3-5个，每8-10个切换维度 |
| 引导 | 教练式对话 + 深挖 + 能量检查（`references/facilitation.md`） | 不提问等回答，延伸用户想法 |
| 收敛 | 触发条件满足时聚类 + 投票 + 行动建议 | 30+想法或用户示意停止时触发 |

---

## 产物输出

| 模式 | 输出路径 |
|------|---------|
| 敏捷模式 | `brainstorm-<主题>.md` |
| 工程模式 | `docs/workflows/{任务ID}/brainstorm.md` |
| 快速模式 | 不落盘，JSON 返回调用方 |

产物模板见 `references/facilitation.md`。

## 依赖关系

| 技能 | 关系 | 说明 |
|------|------|------|
| `adfp-requirement-analyzer` | 后置消费 | 需求模糊时触发快速模式，收敛结果作为需求分析素材 |
| `adfo-harness-runner` | 可选触发 | ANALYZE 前可调度 brainstorm 探索方向 |
| `adfa-dev-helper` | 建议下游 | 用户说"需要创意方案"时推荐本技能 |

## 流程生命周期

```
用户输入 → 模式选择 → 发散(2-5轮) → 能量检查(每4轮) → 正交切换(每8想法) → 收敛 → 输出

异常：能量耗尽(<5) → 强制收敛Top1 | 偏离主题 → 提醒 | 中断 → 整理已有
```

## 职责边界

| 维度 | adfa-brainstorm | adfp-requirement-analyzer | adfa-critical-explorer |
|------|-----------------|--------------------------|----------------------|
| 方向 | **发散创意**，从无到有 | **收敛结构化**，落地执行 | **批判收敛**，找方案漏洞 |
| 阶段 | 项目早期（需求未定义时） | ANALYZE | SPEC/DESIGN 后 |

## 交互原则

| 要做 | 不要做 |
|------|--------|
| 快速响应，每次3-5个 | 冗长解释方法论 |
| 跟随用户能量 | 强制走完所有技术 |
| 延伸用户想法 | 只记录不发展 |
| 适时切换维度 | 停留在舒适区 |

## 约束规则

1. 用户说"停"就停，控制权在用户
2. 快速模式不落盘，直接 JSON 返回调用方
3. 下游技能调用时通过 prompt 传参 `模式: 快速`
4. 不做框架/平台感知——brainstorm 是框架无关的

# 审查详细流程

> 完整审查执行流程，由 `adfp-code-reviewer` SKILL.md 动态加载。

---

## 执行框架

```
读取代码 → 委托adfo-task-orchestrator并行7维度 → 接收汇总 → 高频模式识别 → 问题分级 → 加权评分 → 直接修复 → 生成报告
```

7 个维度互不依赖，委托 `adfo-task-orchestrator` 并发执行（最大并发数: 7）：

```
主 Agent
  ├─ 确定审查目标（git模式/文件/粘贴）
  ├─ 为每个维度生成独立 SubAgent prompt
  ├─ 组织任务清单 → adfo-task-orchestrator
  │
adfo-task-orchestrator
  ├─ 并发组: [SA1~SA7 全部并行]
  ├─ 等待全部完成
  └─ 返回汇总报告
  │
主 Agent
  ├─ 高频模式识别（跨维度）
  ├─ 加权评分
  ├─ 直接修复
  └─ 生成最终审查报告
```

### 任务清单格式

| ID | 描述 | Agent类型 | 提示词 |
|----|------|-----------|--------|
| SA1 | 类型安全 | general-purpose | 检查TS类型正确性：Props接口、any滥用、事件类型、API响应类型、空值处理 |
| SA2 | 框架规范 | general-purpose | 按framework-matrix.md路由检查框架特有规范 |
| SA3 | 性能与体积 | general-purpose | 检查key稳定性、渲染内新对象/函数、重渲染、Bundle体积、大列表虚拟化 |
| SA4 | 边界处理 | general-purpose | 检查Loading/Empty/Error/ErrorBoundary四态、竞态条件 |
| SA5 | 代码质量与复用 | general-purpose | 检查嵌套深度、硬编码、冗余状态、重复逻辑 |
| SA6 | 视觉美学 | general-purpose | 检查字体/色彩/动效/布局的独特性、AI模板化痕迹 |
| SA7 | 副作用分析 | general-purpose | 追踪导出变更、下游调用方、全局状态修改影响 |

## 各维度详细检查（展开版）

### 1. 类型安全
检查：所有 Props 有类型定义、无 `any` 滥用（>2处）、事件处理器类型正确、API 响应有类型、可选链恰当。

### 2. 框架规范
按 `framework-matrix.md` 路由：检查框架特有最佳实践。

### 3. 性能与体积
检查：列表 `key` 稳定性、渲染中创建新对象/函数、不必要重渲染（未 memo 的大列表）、全量引入大型库（>10KB / 2-10KB）、大列表虚拟化、可并行请求串行化。

### 4. 边界处理
检查：Loading / Empty / Error+重试 / ErrorBoundary 四态、竞态条件（AbortController）、边界测试覆盖（→ edga-case-master）。

### 5. 代码质量与复用
检查：深层嵌套（→ 早返回/组件化）、硬编码、冗余状态/可派生数据、重复造轮子、不必要的 JSX 嵌套、import 排序。

### 6. 视觉美学
通用：字体独特性、配色美学方向、动效存在性、空间布局意图、背景层次、AI 模板化痕迹。
框架变体见 `framework-matrix.md`。

### 7. 副作用与影响分析
检查：导出函数/类型变更影响下游、公共工具函数修改（🟡中风险）、接口签名修改（🔴高风险）、全局状态修改、受影响业务链路。

## 严重度定义

| 严重度 | 定义 | 示例 |
|--------|------|------|
| 🔴 critical | 功能正确性或崩溃 | 框架特有泄露（useEffect/watch/onShow）、敏感信息泄露 |
| 🟠 high | 用户体验或可维护性 | 缺少四态、AI模板化美学、any滥用 |
| 🟡 medium | 偏离规范但功能正常 | 组件>200行、嵌套>3层、重复造轮子 |
| 🟢 low | 代码风格建议 | 命名不统一、背景可更有层次 |

## 评分细则

| 维度 | 权重 | 扣分规则 |
|------|------|---------|
| 类型安全 | 15% | any -5/个，缺类型 -3/个 |
| 框架规范 | 15% | 框架特有违规 -10/个 |
| 性能与体积 | 15% | >10KB全量引入 -10/个 |
| 边界处理 | 15% | 缺状态 -5/个 |
| 代码质量与复用 | 15% | 坏味道 -3/个，重复造轮子 -5/个 |
| 视觉美学 | 10% | 每缺1项 -2 |
| 副作用分析 | 15% | 🔴 -10/个，🟡 -5/个 |

## 直接修复规则

**自动修复**：
- 删除 console.log / debugger
- 替换硬编码字符串为常量引用
- 补充缺失的类型标注（非破坏性）
- 删除不必要 JSX 嵌套包装
- 删除解释 WHAT 的冗余注释

**不自动修复**：
- 组件拆分/Hook提取 → 建议 refactor-advisor / hooks-extractor
- 架构级变更 → 标注并建议
- 业务逻辑修改 → 不触及

---

## 异常处理

| 失败类型 | 处理 |
|---------|------|
| 单维度失败 | 重试1次，仍失败标记「待人工审查」 |
| 多维度失败(≥3) | 终止并行，回退串行逐维度 |
| 全部失败 | 输出错误报告 |
| 空文件 | 跳过，标注「文件为空」 |
| Git无变更 | 提示切换模式 |
| 无效hash | 列出最近5个提交 |
| 无效path | 显示当前目录结构 |
| 参数冲突 | 优先级：`--commit` > `--staged` > `--path` > `--file` |

## 产物校验

生成报告后校验：文件存在 → Frontmatter 完整（phase/status/qualityGate/score） → 问题引用准确 → 评分一致 → 结论与评分匹配。
校验失败时在报告末尾添加「校验警告」章节。

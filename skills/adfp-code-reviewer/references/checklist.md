# 代码审查检查清单

完整检查项，按维度展开。SKILL.md 仅保留维度摘要，详细检查规则见本文件。框架感知的变体检查项见 `framework-matrix.md`。

---

## 一、类型安全

- [ ] 所有 Props 有 TypeScript interface 定义
- [ ] 是否存在 `any` 类型滥用（>2处=问题）
- [ ] 事件处理器类型是否正确（如 `React.ChangeEvent<HTMLInputElement>`）
- [ ] API 响应数据是否有类型定义
- [ ] 可选链和空值合并是否恰当使用

## 二、React 规范

- [ ] 组件是否遵循单一职责（单文件 ≤ 200行）
- [ ] useEffect/useMemo/useCallback 依赖数组是否完整
- [ ] 是否存在本地状态可下沉但未下沉
- [ ] 是否存在可提取为自定义 Hook 的重复逻辑（→ 建议 `adfa-code-analysis`（mode:extract））
- [ ] 是否存在组件过大/职责混杂（→ 建议 `adfa-refactor-advisor`）

## 三、性能隐患

- [ ] 列表渲染是否有稳定的 `key`
- [ ] 是否存在渲染中创建新对象/函数的模式
- [ ] 是否存在不必要的重渲染风险（未 memo 的大列表等）
- [ ] Bundle 体积：是否全量引入大型库（lodash/moment/antd 全量）→ 🔴 >10KB / 🟡 2-10KB / 🟢 <2KB gzip
- [ ] 大列表是否使用虚拟化
- [ ] 是否存在可并行但串行执行的独立请求

## 四、边界处理与UX完整性

### 四态覆盖
- [ ] 有 Loading 状态展示（Skeleton / Spin / 加载指示器）
- [ ] 有空状态（Empty）提示（含引导操作，非仅"暂无数据"）
- [ ] 有错误状态 + 重试机制
- [ ] 有 ErrorBoundary 或异常兜底

### 交互反馈完整性
- [ ] 按钮/表单提交有 loading 状态（防止重复提交）
- [ ] 操作成功有反馈（Toast/Message/页面跳转）
- [ ] 操作失败有错误提示（具体错误信息 + 解决路径）
- [ ] 空列表有引导操作（插画/建议/创建按钮）
- [ ] 异步操作有竞态条件处理（AbortController / 取消标记）
- [ ] 弱网/断网场景有友好提示
- [ ] 页面/路由切换有过渡状态

### 测试覆盖
- [ ] 有测试用例覆盖关键边界条件（若无 → 建议 `adfa-edge-case-master`）
- [ ] 有测试覆盖组合状态（如 loading→empty、loading→error 切换）

## 五、代码质量

- [ ] 是否有 3 层以上嵌套（→ 建议早返回/组件化/查找表）
- [ ] 事件处理函数是否以 `handle` 开头
- [ ] 是否存在硬编码的魔法数字/字符串 → 提取常量
- [ ] import 是否按规范排序
- [ ] 是否存在不必要的 JSX 嵌套包装
- [ ] 是否存在冗余状态/可派生数据
- [ ] Code Review 问题类型标记（仅为审查分类使用，非代码注释）：是否存在复制粘贴变体/参数膨胀/泄漏抽象/函数过长
- [ ] 是否存在重复造轮子：新函数与现有 utils 功能重复、内联逻辑可用已有工具替代

## 六、视觉美学

- [ ] 字体选择是否独特（非 Inter/Roboto/Arial/系统默认字体）
- [ ] 配色是否有明确的美学方向（非紫色渐变+白色背景等模板化方案）
- [ ] 是否存在动效（至少一处高影响力动画：页面加载 staggered reveal、滚动触发或悬停惊喜）
- [ ] 空间布局是否有意图性（非默认居中卡片布局）
- [ ] 背景是否有层次/氛围（非纯色背景）
- [ ] 是否存在 AI 模板化美学痕迹（通用设计、缺乏上下文特定性）

## 七、副作用与影响分析

- [ ] 修改了哪些导出函数/类型？（→ 影响所有导入方）
- [ ] 变更对下游调用方的影响（搜索引用位置、追踪调用链至业务入口）
- [ ] 是否修改了公共工具函数？（→ 🟡 中风险）
- [ ] 是否修改了接口定义/类型签名？（→ 🔴 高风险）
- [ ] 是否修改了全局状态/Store？（→ 影响所有消费者）
- [ ] 受影响业务链路是否需要回归测试？

### 影响范围评级

| 等级 | 条件 | 示例 |
|-----|------|------|
| 🔴 高 | 修改公共 API/接口定义/全局状态 | 导出函数签名变更 |
| 🟡 中 | 修改共享逻辑/工具函数 | utils 函数行为变更 |
| 🟢 低 | 修改隔离模块/内部实现 | 私有函数重构 |

---

## 高频问题模式识别

| 模式 | 特征 | 严重性 |
|------|------|--------|
| 内存泄漏 | useEffect 无清理、订阅未取消、定时器未清除 | critical |
| 敏感信息泄露 | 硬编码 token/secret/password/key | critical |
| 错误被吞 | catch 块空实现、只 console.error 不处理 | critical |
| 竞态条件 | 异步操作无 AbortController、fast-click 重复提交 | critical |
| 类型安全 | `any` 类型滥用、缺少类型守卫 | high |
| 缺少兜底 | 无 loading/empty/error 三态处理 | high |
| 操作无反馈 | 点击/提交后无 loading、无成功/错误提示 | high |
| 空状态无引导 | 空列表仅"暂无数据"，无操作引导 | medium |
| N+1 查询 | 循环中逐条请求而非批量获取 | medium |
| 过宽操作 | 读取整个文件只需部分、加载全部只需筛选一个 | medium |

## 加权评分规则

| 维度 | 权重 | 满分条件 | 扣分规则 |
|------|------|---------|---------|
| 类型安全 | 15% | 无类型问题 | 每个 any 滥用 -5，每个缺少类型定义 -3 |
| React 规范 | 15% | 无规范问题 | 每个依赖缺失 -10，超标行数 -3 |
| 性能隐患 | 15% | 无性能问题 + 体积无风险 | 每个 >10KB 引入 -10，无虚拟化 -5 |
| 边界处理与UX完整性 | 15% | 四态齐全 + 交互反馈完整 + 竞态处理 | 每个缺失状态 -5，每个缺失交互反馈 -3 |
| 代码质量 | 15% | 无坏味道 + 无重复造轮子 | 每个坏味道 -3，每个重复 -5 |
| 视觉美学 | 10% | 6 项全部通过 | 每缺失 1 项 -2 |
| 副作用分析 | 15% | 无高/中风险变更 | 每个 🔴 -10，每个 🟡 -5 |

**评分分级**：🟢 优秀 90-100 / 🟡 良好 70-89 / 🔴 需改进 <70

**审查结论**：
- **PASS** ✅：评分 ≥ 90 且无 critical 问题
- **WARN** 🟡：评分 ≥ 70 或仅有 medium/low 问题
- **FAIL** 🔴：评分 < 70 或存在 critical/high 问题

# mode:extract — 可复用逻辑提取

扫描组件代码，识别可提取为自定义逻辑单元的重复逻辑、有状态逻辑块和副作用模式。按框架路由：React → Hooks、Vue → Composables、小程序 → Behaviors。

---

## 流程概述

```
扫描代码 → 平台检测 → 生成 4 SA 任务清单 → 委托 adfo-task-orchestrator 并发扫描 → 去重评分 → 生成提取方案
```

## 4 个扫描维度

通过 `adfo-task-orchestrator` 并发执行（全部无依赖，最大并发 4）：

| ID | 维度 | 扫描目标 | 识别模式 |
|----|------|---------|---------|
| SA1 | 状态组合 | 多个状态变量描述同一业务概念 | `useState` 组 / `ref` 组 → 候选 Hook/Composable |
| SA2 | 副作用逻辑 | 副作用中的业务逻辑 | `useEffect` / `watch` / 生命周期 → 候选提取 |
| SA3 | 重复模式 | 2+ 组件的相似状态+副作用组合 | 跨组件模式 → 候选复用单元 |
| SA4 | 复杂计算 | 多步骤计算链 | `useMemo` / `computed` → 候选计算逻辑 |

> 各框架的扫描模式定义见 `references/extract-patterns.md`，提取模板见 `references/extract-templates.md`

## 评估提取价值

| 维度 | 标准 | 权重 |
|------|------|------|
| 复用性 | 被 2+ 组件使用或很可能被复用 | 30% |
| 内聚性 | 状态和副作用高度相关 | 25% |
| 可测试性 | 提取后可独立单测 | 25% |
| 代码量 | 提取逻辑单元 ≥ 20 行 | 20% |

**评分 ≥ 60% → 建议提取**

## 输出格式

```markdown
---
phase: EXTRACT
status: completed
---

## {Hooks/Composables/Behaviors} 提取建议

### 高优先级（强烈建议提取）
#### use{Name} — {职责描述}
- 提取来源：{文件}:{行号}
- 涉及状态/副作用：{...}
- 提取价值：复用性/内聚性/可测试性（总分 X%）
- 提取后代码：按框架对应模板生成

### 中优先级（建议考虑）
### 低优先级（可选）
```

## 约束规则

1. **只分析，不修改源码** — 用户决定是否提取
2. 提取代码必须返回完整 TypeScript 类型
3. 纯计算逻辑应放入 `utils/` 而非逻辑单元
4. 每个建议说明"为什么值得提取"
5. 命名约定：React/Vue 以 `use` 开头
6. 评分 < 60% 的候选仅作为可选建议，不附带完整代码

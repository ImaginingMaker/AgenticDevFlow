# adfa-hooks-extractor - 评估用例

## 核心场景

| # | 场景 | 预期行为 | 验证方式 |
|---|------|---------|---------|
| 1 | **状态组合提取** — 组件中存在 `useState` 组合 `[loading, error, data]` 共同描述异步数据状态 | SA1（状态组合扫描）识别出 3 个 useState 共同描述同一业务概念，候选为 `useAsyncData()` Hook | 验证输出含候选 Hook `useAsyncData`，提取来源标注文件路径和行号，涉及状态列出 loading/error/data |
| 2 | **副作用逻辑提取** — 组件中 `useEffect` 包含业务逻辑 `fetch().then().catch()` 依赖外部变量 | SA2（副作用逻辑扫描）识别出 useEffect 中的可提取业务逻辑，候选为 `useFetchUser(id)` | 验证输出含候选 Hook 名称以 `use` 开头，含提取前后代码对比 |
| 3 | **重复模式提取** — 2 个组件中存在相似的 `useState + useEffect` 组合 | SA3（重复模式扫描）识别出跨组件的重复状态+副作用组合，候选为复用 Hook | 验证输出标注了 2 个源的组件路径和行号，展示相似代码片段对比 |
| 4 | **复杂计算提取** — 组件中存在多步骤 `useMemo` 计算链 | SA4（复杂计算扫描）识别出多步骤计算链，候选为计算 Hook | 验证输出含计算链步骤拆解和提取后的 Hook 代码 |
| 5 | **4 维度评分 — 建议提取** — 候选 Hook 复用性高、内聚性强、易测试、代码量达标 | 复用性 30% + 内聚性 25% + 可测试性 25% + 代码量 20% = 总分 ≥ 60%，进入「高优先级」建议提取 | 验证输出含 4 维度评分表，总分 ≥ 60%，归类为高优先级 |
| 6 | **4 维度评分 — 不建议提取** — 候选 Hook 总分 < 60% | 总分 < 60%，归类为低优先级，标注「不建议提取」并说明扣分原因 | 验证输出不含生成代码，仅含评分表和「不建议提取」说明 |
| 7 | **SubAgent 并发调度** — 4 个扫描目标同时执行 | 生成含 SA1-SA4 的任务清单，全部无依赖，最大并发数 4，通过 `adfo-task-orchestrator` 调度 | 验证任务清单 ID 为 SA1-SA4，依赖均为空，并发数 = 4 |
| 8 | **结果去重合并** — SA1 和 SA3 同时发现同一个候选 Hook | 主 Agent 合并同一候选的多次发现，评分取各维度的最佳信息综合计算 | 验证最终输出候选 Hook 不重复，标注「由 SA1+SA3 共同发现」 |
| 9 | **生成 Hook 代码含完整类型** — 候选确定提取后输出 Hook 代码 | Hook 代码含 interface Use{Name}Options、interface Use{Name}Return、export function use{Name}，完整 TypeScript 类型定义 | 验证输出代码含 Input/Output 接口定义，函数签名含完整类型标注 |

## 边界测试

| # | 边界情况 | 预期处理 |
|---|---------|---------|
| 1 | 组件中无任何可提取逻辑（纯 UI 展示组件） | 4 个扫描全部返回空候选清单，输出「未发现可提取的模式」，不生成任何 Hook 代码 |
| 2 | 候选 Hook 代码量 < 20 行 | 代码量维度 0 分（权重 20%），总分自动扣减影响，标注「代码量不足，提取收益有限」 |
| 3 | 纯计算逻辑被识别为候选 | 标注「纯计算逻辑应放入 `utils/` 而非 `hooks/`」，建议改为工具函数 |
| 4 | 组件代码中存在语法错误 | 提示「代码存在语法错误，扫描结果可能不完整」，在候选清单中标注「语法异常，跳过该区域分析」 |
| 5 | 跨文件重复模式（2 个组件在不同文件中） | SA3 正常执行跨文件扫描，输出提及 2 个文件路径和公共模式描述 |
| 6 | 候选 Hook 只被 1 个组件使用且无复用前景 | 复用性维度评分低（≤10%），即使其他维度高分总分也难达 60%，标注「当前仅单组件使用」 |
| 7 | 单一扫描维度失败（如 SA3 超时） | 重试 1 次，仍失败则标记该维度为「扫描失败」，基于其他 3 个维度的结果继续处理 |
| 8 | 超大组件（>500 行） | 分块扫描，每块独立分析，报告标注「因组件规模较大，分析可能漏检跨块模式」 |

## 集成测试

| # | 上下游技能 | 集成点 | 预期 |
|---|----------|--------|------|
| 1 | **编排：adfo-task-orchestrator** | 本技能生成 SA1-SA4 任务清单，委托 orchestrator 并发调度 4 个扫描 SubAgent | orchestrator 接收任务清单后同时执行 4 个无依赖 SubAgent，返回各维度候选 Hook 清单 |
| 2 | **上游：adfp-code-reviewer** | code-reviewer 发现可提取的重复逻辑，推荐调用本技能深度扫描 | code-reviewer 报告中标注「建议调用 adfa-hooks-extractor 分析可提取性」，本技能不替代 code-reviewer 的诊断 |
| 3 | **协作：adfp-architecture-designer** | architecture-designer 的 SA2 盘点已有 Hooks（数量+路径），本技能扫描内联逻辑生成新 Hook | architecture-designer 只做盘点不做内联提取，本技能扫描内联逻辑并生成 Hook 代码，职责互补 |
| 4 | **输出：不修改源码** | 本技能只分析不修改源码，提取决定权归用户 | 验证执行后无任何源码文件被修改，仅输出分析报告和代码建议 |

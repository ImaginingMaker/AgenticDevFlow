# SubAgent 委托与聚合协议

> 所有通过 `adfo-task-orchestrator` 调度并发 SubAgent 的技能共享此协议。
> 本文件定义标准化的委托流程、输入输出契约和聚合规范。

---

## 一、委托流程

```
┌─────────────────────────────────────────────────────────────┐
│                        调用方 SKILL                           │
│ 1. 定义 SubAgent 职责 + 生成任务清单（ID/描述/prompt/依赖）    │
│ 2. 通过 Skill 工具委托 adfo-task-orchestrator 执行           │
│ 3. 等待执行结果报告                                          │
│ 4. 执行去重 → 冲突校验 → 按技能特定逻辑聚合 → 输出产物        │
└───────────────────────────┬─────────────────────────────────┘
                            │ 任务清单（结构化表格）
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                   adfo-task-orchestrator                     │
│ 1. 解析任务清单 → 校验（唯一ID / 无循环依赖）                 │
│ 2. 构建 DAG → 识别并发组                                     │
│ 3. 按组调度 SubAgent（并发/串行）                             │
│ 4. 收集结果 → 输出执行报告                                    │
└─────────────────────────────────────────────────────────────┘
```

## 二、任务清单格式

调用方 SKILL 生成如下结构化表格：

| ID | 描述 | Agent类型 | 提示词 | 依赖 |
|----|------|-----------|--------|------|
| SA1 | 职责描述 | general-purpose | 框架感知的完整 prompt | - |
| SA2 | 职责描述 | general-purpose | 框架感知的完整 prompt | - |

**字段说明**：
- **ID**: 唯一标识（SA1, SA2... 或 T1, T2...）
- **描述**: 一句话职责描述
- **Agent类型**: 目前统一使用 `general-purpose`
- **提示词**: 技能特定的完整 Prompt（可含 `{framework}` 变量）
- **依赖**: 前置任务 ID，无依赖则填 `-`

## 三、执行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `最大并发数` | 4 | 同一并发组的 SubAgent 同时执行数 |
| `单任务超时` | 300s | 单个 SubAgent 执行超时 |
| `总超时` | 600s | 全部任务完成的总超时 |
| `失败策略` | continue | continue=继续无依赖任务；abort=立即停止；retry=重试最多 N 次 |

## 四、通用约束规则

| 规则 | 说明 |
|------|------|
| **依赖声明** | 无依赖的 SubAgent 标注 `-`，编入同一并发组并行执行 |
| **维度隔离** | 每个 SubAgent 严格只负责自己维度，不跨维度发言 |
| **去重** | 主 Agent 汇总时必须检测并合并跨 SA 的重叠发现 |
| **冲突校验** | 标记各 SA 发现之间的矛盾点，在主报告中标注 |
| **上下文传递** | 串行链路中下游 prompt 自动拼接上游结果（由 orchestrator 处理） |
| **失败处理** | 单 SA 失败默认继续其他任务，在最终报告中标记「待人工审查」 |

## 五、聚合规范

各技能在 SubAgent 返回后执行自己特定的聚合逻辑，通用步骤如下：

```
接收 all SA 结果 → 去重（合并重叠发现）
    → 冲突校验（标注矛盾点）
    → 按技能特定的组织逻辑分组
    → 输出结构化产物（含 front-matter phase 字段）
```

### 去重原则

- 同一发现被多个 SA 提到 → 合并为一个条目，标注「由 SA{1,3} 共同发现」
- 评分类结果取各维度的最佳信息综合计算
- 冲突类结果保留双方观点，标注「矛盾：SA1 认为 X，SA2 认为 Y」

### 产物要求

| 维度 | 标准 |
|------|------|
| **phase 一致性** | 产物 front-matter 中的 `phase` 必须与当前流水线阶段一致 |
| **内容实质性** | 正文 ≥ 50 字符，不只含 front-matter |
| **下游推荐** | 产物末尾推荐可消费本产物的下游技能（如有） |

# 前端需求多维度协同分析

流水线定位：**ANALYZE 阶段**（PRD 之前）。接收前端需求 → 需求模糊时触发 `adfa-brainstorm` 探索意图 → 需求清晰后并发 3 个 SubAgent 分析 → 输出《前端开发需求协同分析报告》，作为 `adfp-prd-generator` 的输入素材。

---

## 职责边界

### 与上下游技能的定位

| 技能 | 关系 | 输入 | 输出 | 区分 |
|------|------|------|------|------|
| `adfa-brainstorm` | **前置** | 用户模糊想法 | 发散后的创意清单 | 帮助用户**发现**想要什么 |
| **本技能** | ANALYZE | 清晰的需求描述（或 brainstorm 输出） | 需求分析报告（背景+链路+任务） | 将创意**结构化**为可执行的需求 |
| `adfp-prd-generator` | 下游 | 分析报告（本技能输出） | 结构化 PRD | 将分析结果转为标准产品文档 |
| `adfp-spec-generator` | 下游下游 | PRD | 技术规格 | 从 PRD 生成技术架构，深度不同 |
| `adfa-critical-explorer` | 平行 | 已有技术方案 | 批判性评审报告 | **批判性**评审已有方案，本技能是**建设性**分析原始需求 |

### 与 adfa-brainstorm 的协作边界

| 维度 | adfa-brainstorm | adfp-requirement-analyzer |
|------|-------------|------------------------|
| 阶段 | **探索发散**（ANALYZE 之前） | **收敛结构化**（ANALYZE） |
| 目标 | 帮用户发现自己想要什么 | 将想法落地为可执行的需求分析 |
| 触发条件 | 用户需求模糊，无明确方向 | 用户需求清晰（或 brainstorm 已收敛） |
| 输出 | 创意清单 + Top 3 方向 | 需求分析报告（背景+链路+任务） |
| 关系 | 本技能的**前置步骤**，为其提供素材 | brainstorm 的**下游消费者** |

### 与 adfp-prd-generator 的边界

- **本技能**：需求澄清 → 背景分析 → 链路梳理 → 任务计划，产物是「分析报告」
- **adfp-prd-generator**：接收分析报告 → 用户故事 → 功能清单 → 验收标准，产物是「PRD 文档」
- 本技能不生成用户故事和验收标准，那是 PRD 的职责
- 本技能不定义数据模型和 API 契约，那是 SPEC 的职责

### 与 adfa-critical-explorer 的边界

| 维度 | adfp-requirement-analyzer | adfa-critical-explorer |
|------|------------------------|---------------------|
| 意图 | **建设性**：明确要做什么 | **批判性**：找出现有方案的问题 |
| 时机 | 需求刚提出，尚无方案 | 已有方案/设计/代码 |
| Agent 数 | 3 个（背景+链路+任务） | 6 个（需求+逻辑+架构+交互+性能+替代） |
| 输出 | 规划性报告 | 问题清单 + 替代方案 |

## 核心流程

```
用户输入
  │
  ├─ 需求模糊？（只有一句话 / 无方向 / 无 PRD）
  │     └─ YES → 【第零步】触发 adfa-brainstorm
  │                ├─ 模式：标准（15min），聚焦前端功能探索
  │                ├─ 引导方向：功能点、用户场景、核心体验
  │                └─ 收敛后 → 将 Top 3 方向 + 创意清单作为需求素材
  │
  └─ 需求清晰？（有 PRD / 详细描述 / brainstorm 已收敛）
        └─ YES → 【第一步】需求完整性检查 → 【第二步】并发分析 → 【第三步】汇总报告
```

### 第零步：需求明确度判定（决定是否触发 Brainstorm）

分析用户输入的需求明确度：

**需求模糊的信号**（满足任一即判定为模糊）：
- 只有一句话描述，如"我想做个页面"、"帮我做个活动报名"
- 没有提及目标用户或使用场景
- 没有提及核心功能点或只有 1 个模糊功能
- 用户说"我还没想好"、"不太确定"、"你帮我看看"
- 没有任何技术栈偏好或平台说明

**需求清晰的信号**（全部满足则判定为清晰）：
- 有明确的核心目标（我要解决什么问题）
- 有目标用户描述（给谁用的）
- 有 2+ 具体功能点
- 有 PRD 文档或详细需求描述

#### 模糊时：触发 adfa-brainstorm（快速模式）

需求模糊时，通过调用 `adfa-brainstorm` Skill 的**快速模式**探索用户意图。

**委托机制**（按顺序执行）：
1. 告知用户："需求需要进一步明确，先用头脑风暴探索方向"
2. 调用 `adfa-brainstorm` Skill（快速模式），传入用户原始需求描述
3. 等待 brainstorm 返回 Top 3 方向 + 创意清单（JSON 结构化数据）
4. 将 brainstorm 的输出作为需求素材，自动衔接进入第一步（需求完整性检查）

```
🤔 你的需求还需要进一步明确，让我先用头脑风暴帮你探索方向。
   → 调用 adfa-brainstorm（快速模式）
   → 接收 Top 3 方向 + 创意清单
   → 自动衔接结构化分析
```

**异常处理**：
| 情况 | 处理 |
|------|------|
| brainstorm 返回空或无关结果 | 提示用户补充描述，回到需求输入 |
| brainstorm 超时（>15min） | 中断，使用已生成的部分结果 |
| 用户拒绝 brainstorm | 跳过，直接进入第一步，标注「需求未经探索」 |

#### 清晰时：直接进入第一步

```
✅ 需求足够清晰，直接进入结构化分析。
```

### 第一步：需求完整性检查

基于用户输入（或 brainstorm 输出），检查是否包含以下关键信息：
- 需求核心目标
- 目标用户群体
- 核心功能点
- 技术栈偏好
- 截止时间或开发周期

**若信息不完整**，追问补充缺失项（不重复已有内容）：

```
为了更准确地分析，再确认几个信息：
1. {缺失项1}？
2. {缺失项2}？
```

### 第二步：生成任务清单 → 委托 adfo-task-orchestrator

将 3 个分析维度组装为任务清单，委托 `adfo-task-orchestrator` 并发调度执行：

| ID | 描述 | Agent类型 | 提示词 | 依赖 |
|----|------|-----------|--------|------|
| SA1 | 需求背景解析 | general-purpose | 聚焦"为什么做"，拆解业务逻辑... | - |
| SA2 | 开发链路梳理 | general-purpose | 聚焦"怎么做"，梳理技术选型... | - |
| SA3 | 任务计划拆解 | general-purpose | 聚焦"分阶段做"，拆解任务... | - |

3 个维度全部无依赖，同一并发组并行执行。执行参数：`最大并发数: 3`

#### SubAgent 1：需求背景与核心目标解析师

**职责**：聚焦"为什么做"，拆解业务逻辑、用户需求，明确核心价值。

**分析内容**：
1. **业务场景解析**：产品模块、目标用户群体（C端/B端）、使用场景
2. **核心目标提炼**：页面展示、交互体验、性能指标、兼容性、适配终端
3. **潜在需求补充**：推测未明确但必要的需求（响应式、浏览器兼容、无障碍、加载速度）
4. **优先级排序**：按业务价值对需求排序

**输出格式**：
```markdown
## 需求背景与核心目标

### 业务场景
- 产品模块：xxx
- 目标用户：xxx
- 使用场景：xxx

### 核心目标
1. xxx
2. xxx

### 潜在需求（建议补充）
1. xxx
2. xxx

### 业务优先级
- P0：xxx
- P1：xxx
```

#### SubAgent 2：前端开发链路梳理师

**职责**：聚焦"怎么做"，梳理技术选型、依赖条件、衔接节点。

**分析内容**：
1. **技术栈梳理**：推荐框架、组件库、工具，说明选型理由
2. **开发链路拆解**：需求对接→原型确认→UI还原→页面开发→交互实现→接口联调→测试优化→上线部署
3. **依赖条件明确**：UI设计稿、接口文档、后端支持、测试环境等
4. **风险点提示**：接口联调延迟、UI变更、兼容性问题等

**输出格式**：
```markdown
## 前端开发链路梳理

### 技术栈选型
- 框架：xxx（理由：xxx）
- 组件库：xxx
- 工具链：xxx

### 开发链路
需求确认 → 原型/UI设计 → 项目初始化 → 页面开发 → 交互实现 → 接口联调 → 兼容性调试 → 测试修复 → 上线部署

### 依赖资源清单
| 资源 | 优先级 | 状态 |
|------|--------|------|
| xxx  | 高     | 待确认 |

### 链路风险提示
| 风险点 | 规避建议 |
|--------|----------|
| xxx    | xxx      |
```

#### SubAgent 3：开发任务计划拆解师

**职责**：聚焦"分阶段做"，拆解可落地的具体任务。

**分析内容**：
1. **任务拆解**：按模块化、分阶段拆解，每任务含：内容、预估工时、依赖、交付标准
2. **核心任务覆盖**：页面结构、样式、交互逻辑、接口联调、兼容性、性能优化、测试、文档
3. **优先级排序**：P0核心必做、P1重要、P2优化
4. **时间规划**：整体周期、关键里程碑

**输出格式**：
```markdown
## 开发任务计划

### 任务清单
| 任务 | 优先级 | 预估工时 | 依赖 | 交付标准 |
|------|--------|----------|------|----------|
| xxx  | P0     | 2d       | -    | xxx      |

### 时间规划
- 总周期：xx天
- 里程碑1（Day X）：xxx
- 里程碑2（Day X）：xxx

### 任务依赖图
核心功能 → 次要功能 → 优化迭代
```

### 第三步：接收汇总 → 生成报告

`adfo-task-orchestrator` 返回 3 个 SubAgent 结果后，主 Agent 汇总生成完整报告：

```markdown
# 前端开发需求协同分析报告

## 一、需求背景与核心目标
[SubAgent 1 输出]

## 二、前端开发链路梳理
[SubAgent 2 输出]

## 三、开发任务计划
[SubAgent 3 输出]

## 四、总结与建议
- 整体开发周期建议：xxx
- 推荐开发顺序：xxx
- 需用户确认的事项：xxx

## 五、疑问提示
以下事项需进一步确认：
1. xxx
2. xxx
```

## 约束规则

1. **领域限定**：仅聚焦前端开发需求。若用户提出后端、全栈等非前端需求，提示：「本技能仅支持前端开发需求分析，请聚焦前端相关诉求」
2. **Brainstorm 前置**：需求模糊时必须先触发 `adfa-brainstorm`，不跳过发散直接分析。brainstorm 的引导细节（模式选择、技术选用、收敛节奏）由 brainstorm 自身管理，本技能只做「判定+委托+衔接」
4. **效率要求**：Brainstorm 控制在 15 分钟内收敛；SubAgent 并发执行，整体不超过 5 分钟
5. **需求边界**：严格按用户需求拆解，不擅自增加无关功能。潜在需求标注「建议补充」，由用户确认
6. **技术选型**：贴合前端行业主流方案，兼顾实用性与兼容性
7. **不替代下游**：不生成用户故事（PRD职责）、不定义 API 契约（SPEC职责）、不展开组件树（DESIGN职责）

```markdown
- 链路拆解粒度：粗粒度（阶段级）/ 细粒度（任务级）
- 任务预估工时单位：天 / 小时

## 默认技术偏好
- 框架优先：{用户指定，如 React / Vue / 小程序原生}
- UI 库优先：{用户指定}
- 目标平台：Web / H5 / 小程序 / 桌面端

## 报告偏好
- 是否包含竞品参考：是 / 否
- 是否包含技术选型对比：是 / 否
```

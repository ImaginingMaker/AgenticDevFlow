# adfp-requirement-analyzer - 评估用例

## 核心场景

| # | 场景 | 预期行为 | 验证方式 |
|---|------|---------|---------|
| 1 | 完整需求输入 | 输出完整的《前端开发需求协同分析报告》，包含需求背景与核心目标、前端开发链路梳理、开发任务计划、总结与建议、疑问提示五个部分 | 检查报告结构完整性 |
| 2 | 信息不完整的需求（但需求方向清晰） | 先追问用户补充关键信息（目标用户、技术栈、截止时间等），而非直接分析 | 检查输出包含追问内容 |
| 3 | 需求模糊（只有一句话，无方向） | 先触发 `adfa-brainstorm` 标准模式探索意图，收敛后再进入分析 | 检查输出包含 brainstorm 引导语，且 brainstorm 收敛后有衔接语 |
| 4 | 非前端需求 | 拒绝并提示「本技能仅支持前端开发需求分析」 | 检查拒绝消息 |
| 5 | 用户已有 PRD 文档 | 跳过第零步（brainstorm），直接进入完整性检查 + 并发分析 | 检查不出现 brainstorm 引导语 |

## 边界测试

| # | 边界情况 | 预期处理 |
|---|---------|---------|
| 1 | 空输入 / 极简描述（如"做个页面"） | 触发 brainstorm，引导用户探索方向和功能 |
| 2 | 需求包含后端+前端混合内容 | 仅分析前端部分，提示后端部分不在范围内 |
| 3 | 需求中技术栈不合理（如小程序用 React） | SubAgent 2 在技术选型中标注并给出合理替代 |
| 4 | 3 个 SubAgent 返回结果有冲突 | 汇总时标注冲突点，让用户确认 |
| 5 | 需求已非常详细（含完整 PRD） | 跳过 brainstorm，精简分析，建议用户直接进入 PRD 阶段 |
| 6 | Brainstorm 中用户提前说"够了" | 立即收敛，产出 Top 3，衔接进入第一步分析 |
| 7 | 用户在 brainstorm 中改变方向 | 以新方向为准，收敛后分析新方向 |

## 集成测试

| # | 上下游技能 | 集成点 | 预期 |
|---|----------|--------|------|
| 1 | `adfa-brainstorm` | 模糊需求 → brainstorm 发散 → 收敛 → 本技能分析 | brainstorm 输出被本技能直接引用为需求素材 |
| 2 | `adfp-prd-generator` | 分析报告 → PRD 输入 | PRD 生成器能直接引用分析报告中的需求背景和功能清单 |
| 3 | `adfa-critical-explorer` | 触发词区分 | "帮我分析这个需求"触发本技能，"帮我评审这个方案"触发 critical-explorer |
| 4 | `adfo-harness-runner` | ANALYZE 阶段调度 | 编排器能从 ANALYZE 正常流转到 PRD |
| 5 | `adfp-spec-generator` | 职责不重叠 | 本技能不做数据模型、API 契约设计，那是 SPEC 的职责 |

# Brainstorm 联动流程

> 当用户需求模糊时，`adfp-requirement-analyzer` 自动触发 `adfa-brainstorm`（快速模式）探索意图。

## 触发条件

用户输入出现以下模糊信号之一时，判定为需求模糊：

| 模糊信号 | 示例 |
|---------|------|
| 一句话需求 | "帮我做个登录"、"想做个商城" |
| 无目标用户 | 未说明谁使用、什么场景 |
| 无功能点 | 只说概念，没有具体功能描述 |
| 用户表示不确定 | "还没想好"、"大概就是……"、"可能……" |
| 需求范围过大 | "做一个像淘宝一样的" |
| 需求多义性 | 同一句话可被理解为多个不同的功能方向 |

## 执行流程

```
用户输入 → 明确度判定
  ├─ 清晰 → 直接进入 3 SubAgent 阶段
  └─ 模糊 → 第零步：触发 brainstorm（快速模式）
                ├─ 目标：15 分钟内收敛到 Top3 方向
                ├─ 输出：3 个候选方向的简要描述 + 每个方向的置信度
                └─ 接收用户选择 → 以选定方向作为需求输入进入 SubAgent
```

### 第零步详细步骤

1. **判定模糊**：需求明确度判定器检查信号
2. **通知用户**：
   ```
   需求描述较为模糊，👉 正在启动头脑风暴快速模式（adfa-brainstorm）
   帮你明确方向，预计 15 分钟内收敛到 3 个候选方向。
   ```
3. **触发 brainstorm**：调用 `adfa-brainstorm` 快速模式
4. **等待输出**：接收 brainstorm 的 Top3 方向
5. **用户确认**：
   ```
   已为你梳理出 3 个可能的方向：

   方向 A：{1句话描述}（置信度：高/中/低）
   方向 B：{1句话描述}（置信度：高/中/低）
   方向 C：{1句话描述}（置信度：高/中/低）

   请选择你要深入的方向（可单选或组合）：
   ```
6. **接收选择**：用户选择后，以选定方向作为需求输入
7. **进入主流程**：跳过明确度判定，直接进入 3 SubAgent 并发分析

## 收敛约束

| 约束 | 值 |
|------|-----|
| 最大发散时间 | 15 分钟 |
| 输出方向数 | Top 3（不多不少） |
| 每个方向描述 | ≤ 2 句话 |
| 置信度标注 | 高/中/低 |

## 跳过条件

- 用户直接说"不用 brainstorm，直接分析"→ 跳过，按清晰需求处理
- 用户提供了完整的功能列表 → 跳过

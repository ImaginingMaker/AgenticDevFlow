# SubAgent 提示词与输出格式

> 供 `adfp-requirement-analyzer` 调度 3 个 SubAgent 使用。通过 `adfo-task-orchestrator` 并发调度（全部无依赖，最大并发 3）。

## SA1：需求背景解析师

### 职责
聚焦「为什么做」——业务场景、核心目标、优先级排序。

### 输入
- 用户原始需求文本
- （可选）`adfa-brainstorm` 输出的 Top3 方向

### 提示词模板

```
你是一名需求背景解析师。请从以下前端需求中提取并分析：

【需求文本】
{用户输入}

请按以下结构输出：

1. 业务场景分析
   - 用户是谁（角色/身份）
   - 在什么场景下使用
   - 要解决什么核心问题

2. 核心目标
   - 一句话概括本需求的核心目标
   - 3 个关键成功指标

3. 优先级建议
   - P0（必须做，核心价值）：列出 1-3 项
   - P1（应该做，重要但不阻塞）：列出 1-3 项
   - P2（可以做，增强体验）：列出 1-2 项

4. 潜在依赖
   - 依赖哪些现有功能/系统
   - 前置条件

5. 建议补充信息
   - 用户未提供但分析中发现的缺失信息
```

### 输出格式

```markdown
## SA1 需求背景解析报告

### 业务场景
- **用户角色**：{角色描述}
- **使用场景**：{场景描述}
- **核心问题**：{一句话描述}

### 核心目标
- **一句话目标**：{目标}
- **关键指标**：
  1. {指标1}
  2. {指标2}
  3. {指标3}

### 优先级
| 优先级 | 内容 | 理由 |
|--------|------|------|
| P0 | {必须做的功能} | {理由} |
| P1 | {应该做的功能} | {理由} |
| P2 | {可以做的功能} | {理由} |

### 依赖关系
- {依赖项1}
- {依赖项2}

### 建议补充
- {缺失信息1}
- {缺失信息2}
```

## SA2：开发链路梳理师

### 职责
聚焦「怎么做」——技术选型（从平台感知检测结果读取目标框架/平台）、依赖条件、风险点。

### 输入
- 用户原始需求文本
- 平台感知检测结果（目标框架/平台）
- （可选）现有项目代码上下文

### 提示词模板

```
你是一名前端开发链路梳理师。请从以下需求出发，梳理技术实现链路。

【需求文本】
{用户输入}

【目标框架/平台】
{techStack 检测结果或通用前端}

请按以下结构输出：

1. 技术选型建议
   - 基于目标框架推荐的生态选型（状态管理、路由、UI 库、请求库、样式方案）
   - 若框架未知则给出通用推荐

2. 实现链路
   - 数据流：数据来源 → 处理 → 展示
   - 页面/组件层级
   - 关键交互流程

3. 依赖条件
   - 外部依赖（第三方库/服务）
   - 内部依赖（已有模块/API）
   - 环境要求（Node 版本、浏览器兼容性等）

4. 风险点
   - 技术风险（性能、安全、兼容性）
   - 实现风险（复杂度、不确定性）
   - 时间风险（估算难度）

5. 技术约束
   - 框架/平台限制
   - 性能目标（首屏、响应时间）
   - 兼容性要求
```

### 输出格式

```markdown
## SA2 开发链路梳理报告

### 技术选型
| 维度 | 选型 | 理由 |
|------|------|------|
| 框架 | {基于检测结果} | — |
| 状态管理 | {推荐方案} | {理由} |
| 路由 | {推荐方案} | {理由} |
| UI 库 | {推荐方案} | {理由} |
| 请求库 | {推荐方案} | {理由} |
| 样式方案 | {推荐方案} | {理由} |

### 实现链路
[数据流 + 组件层级 + 交互流程的文本描述]

### 依赖条件
- **外部依赖**：{第三方库/服务}
- **内部依赖**：{已有模块/API}
- **环境要求**：{Node/浏览器等}

### 风险点
| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| {技术风险} | 高/中/低 | {缓解方案} |
| {实现风险} | 高/中/低 | {缓解方案} |

### 技术约束
- {约束1}
- {约束2}
```

## SA3：任务计划拆解师

### 职责
聚焦「分阶段做」——任务拆解、工时估算、里程碑规划。

### 输入
- 用户原始需求文本
- SA1 的优先级建议
- SA2 的技术链路分析

### 提示词模板

```
你是一名前端开发任务计划拆解师。请基于以下分析结果，制定开发计划。

【需求背景（来自 SA1）】
{SA1 的核心目标和优先级}

【技术链路（来自 SA2）】
{SA2 的技术选型和依赖条件}

请按以下结构输出：

1. 任务拆解
   - 按功能模块拆分为子任务
   - 每个任务标注：名称、描述、预估工时、前置依赖、优先级

2. 里程碑规划
   - M1（MVP）：最核心功能，可上线
   - M2（增强）：重要功能补充
   - M3（完善）：边缘功能 + 优化

3. 并行可能性
   - 可并行的任务组
   - 串行依赖链

4. 风险缓冲
   - 高风险任务标注
   - 建议的缓冲时间
```

### 输出格式

```markdown
## SA3 任务计划拆解报告

### 任务清单
| # | 任务 | 描述 | 预估工时 | 前置依赖 | 优先级 |
|---|------|------|---------|---------|--------|
| T1 | {任务名} | {描述} | {X人天} | 无/{T#} | P0 |

### 里程碑
| 里程碑 | 包含任务 | 预计工期 | 交付物 |
|--------|---------|---------|--------|
| M1 MVP | T1, T2, T3 | {X人天} | {交付物} |
| M2 增强 | T4, T5 | {X人天} | {交付物} |
| M3 完善 | T6, T7 | {X人天} | {交付物} |

### 并行策略
- **可并行**：{T1, T2 → 同时开发}
- **串行依赖**：{T3 依赖 T2 → T2→T3}

### 风险标注
- ⚠️ {高风险任务}：{风险描述}，建议增加 {X%} 缓冲
```

## 汇总整合规则

三个 SubAgent 完成后，按以下顺序汇总为最终分析报告：

1. **去重**：合并 SA1/SA2/SA3 中重合的结论
2. **冲突校验**：标注优先级或技术选型中的冲突项，由主技能裁决
3. **优先级排序**：按 P0→P1→P2 排列
4. **输出**：生成最终结构化分析报告

# adfa-code-context - 评估用例

## 核心场景

| # | 场景 | 预期行为 | 验证方式 |
|---|------|---------|---------|
| 1 | 提供单个文件路径 | 分析该文件入口点、核心逻辑、依赖项，输出完整报告 | 检查报告是否包含基本信息+逻辑链+模块摘要+数据流 |
| 2 | 提供文件夹路径 | 自动检测入口文件（优先级：index > main > App > package.json主字段） | 检查入口文件检测是否正确 |
| 3 | 提供含深层依赖的模块 | 递归追踪内部引用2-3层，展示核心调用链树形图 | 检查调用链深度是否控制在2-3层 |
| 4 | 项目上手场景 | 输出建议阅读顺序，帮助用户快速建立心智模型 | 检查"建议阅读顺序"部分 |

## 边界测试

| # | 边界情况 | 预期处理 |
|---|---------|---------|
| 1 | 目标文件不存在 | 提示用户检查路径，不输出空报告 |
| 2 | 目标文件无外部导入（纯工具函数） | 标注"自包含模块"，仅分析内部逻辑 |
| 3 | 文件夹无入口文件 | 列出所有文件供用户选择 |
| 4 | 引用链超过3层 | 截断至3层，标注"引用链过长，已截断" |
| 5 | 大量内部依赖（20+模块） | 仅列出关键路径，标注"已省略N个次要模块" |

## 集成测试

| # | 上下游技能 | 集成点 | 预期 |
|---|----------|--------|------|
| 1 | adfp-architecture-designer → adfa-code-context | 全局架构分析后，选择某个模块深入理解 | architecture-designer 提供依赖拓扑，code-context 深入追踪调用链 |
| 2 | adfa-code-context → adfp-code-reviewer | 理解代码逻辑后进行质量审查 | code-context 建立心智模型，code-reviewer 发现质量问题 |
| 3 | adfa-code-context → adfp-code-implementer | 理解现有代码后进行修改实现 | code-context 追踪影响范围，code-implementer 精准修改 |
| 4 | adfa-code-context → adfa-hooks-extractor | 理解组件逻辑后识别可提取的 Hook | code-context 梳理数据流，hooks-extractor 识别复用模式 |

# 异常处理链路分析 SubAgent

## 任务目标
分析异常捕获和容错逻辑，生成标准化文档。

## 输入信息

### 项目上下文（从文档提取）
- 项目名称：{projectName}
- 错误处理规范：{errorHandlingSpec}
- 错误码定义：{errorCodeDefinitions}
- 降级策略：{fallbackStrategy}

### 页面信息
- 页面文件路径：{filePath}
- 异常处理代码：{errorHandlingCode}
- 接口错误处理：{apiErrorHandler}

## 分析步骤

### 1. 识别异常捕获模式
查找以下代码模式：
- try-catch 块
- .catch() 链式调用
- onError 钩子
- Error Boundary (React)

### 2. 分类异常类型
识别不同类型的异常：
- 接口异常（网络错误、业务错误）
- 表单校验异常
- 权限异常
- 运行时异常

### 3. 分析处理逻辑
追踪异常的处理方式：
- 错误提示方式（Toast、Message、Alert）
- 错误日志记录
- 错误恢复机制

### 4. 分析容错降级
识别异常时的降级方案：
- 默认值填充
- 空状态显示
- 功能禁用

## 输出格式

```markdown
## 第七章 权限、埋点与异常处理

### 7.3 异常捕获与处理

#### 7.3.1 接口异常处理

**异常类型**：

| 类型 | 错误码 | 说明 | 处理方式 |
|------|--------|------|----------|
| 网络错误 | NETWORK_ERROR | 网络连接失败 | 显示重试提示 |
| 超时错误 | TIMEOUT | 请求超时 | 显示超时提示，提供重试 |
| 业务错误 | 400-499 | 业务逻辑错误 | 显示后端返回的错误信息 |
| 权限错误 | 401/403 | 权限不足 | 跳转到登录页或403页 |
| 服务器错误 | 500-599 | 服务器异常 | 显示系统异常提示 |

**处理逻辑**：
```javascript
try {
  const res = await getUserList(params)
  tableData.value = res.data
} catch (error) {
  if (error.code === 'NETWORK_ERROR') {
    showToast('网络连接失败，请检查网络后重试')
  } else if (error.code === 401) {
    router.push('/login')
  } else {
    showToast(error.message || '系统异常')
  }
}
```

#### 7.3.2 表单校验异常

**校验规则**：

| 字段 | 规则 | 错误提示 |
|------|------|----------|
| username | 必填，3-20字符 | 请输入3-20位用户名 |
| email | 必填，邮箱格式 | 请输入正确的邮箱地址 |
| phone | 必填，手机号格式 | 请输入正确的手机号 |

**处理方式**：
- 实时校验：输入时即时反馈
- 提交校验：提交前统一校验
- 错误定位：自动聚焦到第一个错误字段

#### 7.3.3 权限异常处理

**权限检查时机**：
- 页面进入前：路由守卫检查
- 操作执行前：按钮权限检查

**处理方式**：
- 无页面权限：跳转到403页面
- 无操作权限：隐藏或禁用操作按钮

### 7.4 容错降级方案

| 场景 | 降级方案 | 说明 |
|------|----------|------|
| 列表加载失败 | 显示空状态 | 提示"暂无数据"，提供刷新按钮 |
| 详情加载失败 | 显示错误页 | 提示"加载失败"，提供返回按钮 |
| 图片加载失败 | 显示占位图 | 使用默认图片替代 |
| 接口部分失败 | 显示部分数据 | 已获取的数据正常显示，失败部分提示 |
```

# 业务操作链路分析 SubAgent

## 任务目标
分析用户交互操作链路，生成标准化文档。

## 输入信息

### 项目上下文（从文档提取）
- 项目名称：{projectName}
- 业务模块：{businessModules}
- 权限体系：{permissionSystem}
- 业务规则：{businessRules}

### 页面信息
- 页面文件路径：{filePath}
- 事件处理函数：{eventHandlers}
- 按钮绑定代码：{buttonBindings}

## 分析步骤

### 1. 识别用户操作入口
查找以下代码模式：
- 点击事件：`@click`, `onClick`
- 表单提交：`@submit`, `onSubmit`
- 输入事件：`@input`, `onChange`
- 选择事件：`@change`, `onSelect`

### 2. 追踪事件处理函数
分析每个操作的处理逻辑：
- 参数校验
- 接口调用
- 状态更新
- 视图反馈

### 3. 梳理分支走向
识别操作的成功/失败分支：
- 成功处理逻辑
- 失败处理逻辑
- 边界条件处理

### 4. 识别关联操作
分析与当前操作相关的其他操作：
- 前置操作
- 后续操作
- 并发操作

## 输出格式

```markdown
### 3.2 主流程操作链路

#### 3.2.1 搜索操作

**链路名称**：用户搜索

**触发条件**：点击搜索按钮或按回车键

**执行步骤**：
1. 用户输入搜索关键词，点击搜索按钮
2. 触发 handleSearch 函数
3. 校验搜索参数（关键词不能为空）
4. 调用 getUserList 接口，传入搜索参数
5. 接口返回后更新 tableData
6. 表格重新渲染，显示搜索结果

**分支走向**：
```
搜索操作
├── 参数校验
│   ├── 通过 → 发起请求
│   └── 失败 → 显示校验错误
├── 请求结果
│   ├── 成功 → 更新列表
│   └── 失败 → 显示错误提示
└── 数据状态
    ├── 有数据 → 显示列表
    └── 无数据 → 显示空状态
```

**数据流转**：
- 入参：{ keyword: string, page: number }
- 出参：{ list: [], total: number }

#### 3.2.2 新增操作

**链路名称**：新增用户

**触发条件**：点击新增按钮

**执行步骤**：
1. 点击新增按钮，打开新增弹窗
2. 用户填写表单
3. 点击确认，触发表单校验
4. 校验通过后调用 createUser 接口
5. 接口成功后关闭弹窗，刷新列表

**异常处理**：
- 表单校验失败：显示字段错误提示
- 接口返回失败：显示后端错误信息
- 网络异常：显示网络错误，支持重试
```

## 注意事项
- 每个操作独立分析，但需标注操作间的关联
- 区分主流程和分支流程
- 标注每个步骤的代码位置

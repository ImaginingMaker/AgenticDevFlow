# adfa-dev-helper - 评估用例

## 核心场景

| # | 场景 | 预期行为 | 验证方式 |
|---|------|---------|---------|
| 1 | **进度速览 — 有活跃任务** — 用户问「进度怎么样」| 扫描 `docs/workflows/` 下所有 `state.json`，过滤非终态任务，输出状态仪表盘含活跃任务数、已完成数、每任务当前阶段/进度条/状态（正常/阻塞/已完成），列出所有阻断项 | 验证输出含 📊 标题、任务列表（含阶段、进度条、状态图标）、阻断项列表 |
| 2 | **进度速览 — 无活跃任务** — 新项目 `docs/workflows/` 不存在 | 输出「当前没有活跃的开发任务」，给出快速开始建议（推荐 PRD / 组件设计 / 代码实现三种入口） | 验证输出不含任务表格，含快速开始三段式建议 |
| 3 | **场景分析 — 明确场景** — 用户说「帮我看下这段代码复用性」 | 识别为 Hooks 提取场景，推荐 `adfa-hooks-extractor`，附带推荐理由 | 验证推荐技能包含技能名和「为什么选这个」的理由说明 |
| 4 | **场景分析 — 完整开发链路推荐** — 用户说「我要从头做一个新项目」 | 推荐完整 8 步正向流水线链路：requirement-analyzer → PRD → SPEC → architecture-designer → component-designer → code-implementer → code-reviewer | 验证输出含完整链路箭头连接图 |
| 5 | **场景分析 — 快速原型链路** — 用户说「快速做一个原型验证一下」 | 推荐跳过文档阶段的快速链路：architecture-designer（分析复用）→ code-implementer | 验证推荐链路不含 PRD/SPEC/DESIGN 阶段 |
| 6 | **下一步建议 — 有当前阶段产物** — 用户说「我刚做完了 SPEC，下一步呢」| 识别当前阶段为 SPEC，产物为 `spec.md`，推荐下一步「架构设计与实施规划」→ `adfp-architecture-designer` | 验证输出含当前阶段名、推荐技能名和理由 |
| 7 | **下一步建议 — 审查失败后** — 用户说「审查没通过」 | 识别为 REVIEW FAIL 场景，推荐修复模式，调用 `adfp-code-implementer（修复模式）` | 验证推荐为修复模式而非新建任务 |
| 8 | **场景不明确 — 主动询问** — 用户说「我不知道该做什么」| 主动询问三要素：你在哪个阶段？手头有什么产出？想要什么产出？ | 验证输出含 🤔 引导，至少包含「阶段/手头产物/目标产出」三个问题 |
| 9 | **场景分析 — 并发/并行场景** — 用户说「我要同时处理多个任务」 | 推荐 `adfo-task-orchestrator`，说明其 DAG 拓扑调度 SubAgent 并发执行的能力 | 验证推荐词含「DAG 拓扑调度」和「并发执行」关键词 |
| 10 | **只读不写** — 执行进度速览后检查是否有写操作 | 仅读取 `state.json` 和文件系统，不做任何状态修改、文件创建、删除、内容变更 | 验证调用完成后 `state.json` 的 mtime 未变化，无新增文件 |

## 边界测试

| # | 边界情况 | 预期处理 |
|---|---------|---------|
| 1 | `docs/workflows/` 存在但所有任务均为 DONE/FAILED 终态 | 视为无活跃任务，输出提示并给出快速开始建议 |
| 2 | `state.json` 文件损坏无法解析 JSON | 读取失败时回退到文件系统扫描，输出「状态文件异常，以下信息基于文件系统推断」的提示 |
| 3 | `docs/workflows/` 目录存在但无任何 `state.json` | 基于目录结构和文件名推断任务信息，标注「基于文件系统推断，建议初始化 harness-runner 建立状态追踪」 |
| 4 | 用户说「不需要建议了」 | 立即停止输出建议内容，回复「好的，有需要随时找我」 |
| 5 | 场景分析中用户描述的场景同时匹配多个技能 | 列出所有匹配技能及其理由，标注优先级建议（如「推荐首选…其次是…」） |
| 6 | 用户当前阶段产物存在多个（如同时有 SPEC 和 architecture.md） | 取最新完成阶段作为当前阶段，推荐其下一步 |
| 7 | 场景分析中用户只是简单问候（「你好」「在吗」） | 不触发场景分析，友好回复并询问需要什么帮助 |
| 8 | step 0：你说我现在在哪个环节 | 需求 / 设计 / 开发 / 审查 / 重构 |

## 集成测试

| # | 上下游技能 | 集成点 | 预期 |
|---|----------|--------|------|
| 1 | **对照：adfo-harness-runner**（职责隔离） | dev-helper 只读不写，harness-runner 管理状态和流水线 | dev-helper 不创建/修改/删除任何 state.json 或文件；harness-runner 是唯一修改状态的能力者 |
| 2 | **依赖：.claude/skills/README.md 注册中心** | 场景→技能映射表和下一步建议表均从注册中心派生 | dev-helper 不硬编码技能列表，映射关系与 README.md 注册中心一致 |
| 3 | **参考：phase-registry.md** | 下一步建议的阶段→技能映射从 harness-runner 的 phase-registry.md 派生 | 下一步建议与 phase-registry.md 的完整阶段映射一致 |
| 4 | **下游：各 adfp/adfa/adft 技能** | 推荐技能时附带调用理由，用户可直接按推荐调用 | 推荐中附带的理由包含「为什么选这个」而非仅列技能名 |
| 5 | **上游：docs/workflows/{任务ID}/state.json** | 进度速览功能读取 state.json 的 currentPhase、phaseHistory、blockers | 仪表盘显示的阶段/进度/阻断项与实际 state.json 内容一致 |
